# Managed uninstall boundary model

One originally published/native-owned artifact, two conflicting operation keys,
one retained recovery-copy duty, exact Stop/lock facts and source result CAS.
No recursive deletion, service-manager shutdown, data purge or new-key retry is
modeled. A copied helper is never authority by itself. The model separates
copy-intent from copy execution/outcome, removal intent from unlink and observed
absence, native completion from source coordination settlement, and read access
from mutation rights. Focused component validation: finite19,320 distinct states, five actual Go
histories (six named test outcomes),165 full state records/160 adjacent edges
and final TLC witnesses,17 altered actual histories refused, and85 TLAPM
obligations proved. Independent review is required before feature integration.
These are scoped component results; the real CLI/SSH transport and UI remain
separate evidence. Earlier formal1/proof79 is retained as historical because
its lost outer reply was not yet reflected in the model.

The existing Stop theorem is an explicitly separate boundary: a positive native
inspection must match the original desired-stopped row, original generation,
drain-ready record and joined marker while holding its actual daemon lock. This
model does not synthesize those facts from a disconnected transport or PID. The
new actual trace will use a real private Serve/join/WithInspectedNodeStop callback
for positive removal; filesystem-only controls will be labeled separately.

`ownershipFresh` and `mutationRight` are values observed at actual checks, not a
continuous OS/filesystem isolation guarantee. `CheckRemove` binds that check to
the retained original attempt; observed scope changes invalidate it. Native
checks and unlink are not one atomic system call. The backend's daemon lock does
serialize supported restart with removal. OS service ownership is outside scope.

Read-only inspection never grants removal. New-key admission cannot bypass a
copy-intent/unknown duty. An unknown unlink acknowledgment retains remove-intent;
observed absence does not fabricate a causally completed receipt. Source CAS can
settle only a positive original removed result with joined source ownership;
completion cannot regress on a later unavailable inspection. No timeout is a join.

Implementation work will reuse scripts/test-formal.py Gate and the original
formal_process.py owner. Bound each actual Go package to120s/native150s; TLC512MiB,
one worker/180s; TLAPM300s. Required projection checks cover full initial states,
every Next edge, exact final witnesses and altered actual records. Trace payloads
contain public identity/grant revision/native IDs and original receipt hashes;
never raw private configuration, key material or endpoint tokens.

`lockHeld` represents the original maintenance-action permission interval.
`native-leave` occurs before deferred read-source close/Flock unlock/lock close,
and proves no physical unlock, FD absence or generic native-owner join. The
original Stop boundary remains separate and unchanged. Observations check exact
original target/actor/generation/current stopped state, original native IDs and
current named path. They do not promise continuous filesystem or grant isolation
between separate native calls.

Copy intent precedes any recovery payload allocation. Unknown copy cannot acquire
a new-key escape. Removal intent precedes the one unlink attempt within a native
maintenance interval. A new explicit finish review is needed to enter a later
interval; readonly lookup never rearms it. Receipt `remove-intent` plus observed
absence does not invent a completed removal receipt. A real outer finish error
retains `returnedUnknown` even if the durable removed record/effect already
exists. Only positive exact original-key lookup clears that uncertainty; source
CAS cannot newly complete while it remains unknown. Completed source results
remain monotone on later inspection errors.
