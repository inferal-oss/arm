# Semblance catalog audit

Audit source: clean upstream `0db58805c6f70e4ef281c17ecf2b53ad947dd984`, all ontology load-list files, component groups, design/build docs, gallery and relevant tests. The catalog has 230 grouped terms, including widgets, internal components, mixins, events and supporting vocabularies. They are not 230 independent widgets.

## Application decisions

| ARM need | Stock choice | Reason |
| --- | --- | --- |
| App chrome/display | AppBar, Segmented, Choice, ThemeSwitcher, StatusBar | Native responsive More actions and graph state; stock Semblance default. |
| Monitor | Stat, Grid, Card, Progress, DescriptionList, IconButton | Clear dominant reading, aligned facts, compact explanations, stock responsive placement. |
| Telemetry history | Sparkline upstream candidate | Current LineChart is positive/logarithmic and unsuitable for zero/gaps; reusable explicit-point linear projection proposed in #155. |
| Live activity | Timeline inside side-attached Drawer | Bounded recent stream, separate durable history and explicit pause while reading. |
| Conversation | MessageList with c:content bodies | Message avatars/time/log semantics; body composes text, badges, reply and lease actions. |
| Search/actions | CommandPalette, SearchField, Toolbar, ButtonGroup | Use typed bound search and labelled wrapping groups, not anonymous stacks. |
| Pool hierarchy (selection candidates) | Tree + selected detail, Table/DescriptionList, Stepper | Existing tree selection handles hierarchy; review remains explicit, keyed and revision-bound. |
| Long selections | Combobox/Typeahead | Reported node and exact recipient choices can show searchable labels. Never turn option selection into execution. |
| Metadata/exact JSON | JsonTree when exact/bounded | Existing parser currently rounds large JSON numbers and lacks expansion budgets; retain exact raw representation until fixed upstream. No new JSON widget needed. |
| Pending/empty/errors | Spinner, EmptyState, Alert, Badge | Honest unknown and error states with built-in announcements. |
| Help and decisions | Dialog/Popover/AccordionItem | Reuse dismissal, focus, keyboard and themes. Existing PRs cover explicit close/focus, so do not duplicate. |
| Mesh graph | Tree/Outline/ResultGraph only when semantically appropriate | Authority and route facts stay explicit; a diagram must not imply authorization. |
| Screen | ext:Island for framebuffer and private inputs only | The protocol renderer owns canvas; private input values must not enter RDF/LDES. Surrounding UI stays stock. |

Preformatted review values must not be inferred as JavaScript numbers. Tables
use the stock column `c:format "code"` contract. Description lists use the stock
`c:of`/`c:fields` contract with labelled resource values, preserving exact counts,
leading zeroes and numeric-looking names. No replacement component is needed.
Raw exact JSON remains bounded Code until the JsonTree candidate is accepted.

The complete grouped inventory follows. Applicability is a design decision, not a requirement to use every component. Inspection/workbench, sheet, calendar, gallery and movable-window features are available but are not automatically useful in an operator dashboard.

## Actions

| Term | Contract |
| --- | --- |
| `Button` | An actionable control. What it does is a behaviour-layer binding. |
| `ButtonGroup` | An attached row of buttons (c:children): one outline, shared inner borders. A sty:size on the group sizes every button in it (the size's custom properties inherit). c:label names the group for assistive technology (role=group). |
| `IconButton` | A square, icon-only button: the glyph is c:icon and the accessible name (aria-label, and its tooltip) is c:label. Toned (sty:tone, sty:emphasis; soft by default) and sized (sty:size). With c:pressed it is a toggle button (aria-pressed); what it does is a behaviour-layer binding. |
| `Menu` | A menu button: a trigger (c:label, optional c:icon) that discloses c:items, a list of c:MenuItem. c:open holds whether the menu is shown; clicking the trigger flips it, and Escape closes it (the open trigger declares the keyboard layer's escape shortcut). Toned and sized like a button. Items are only built while the menu is open. |
| `MenuItem` | An entry of a c:Menu: c:label, optional c:icon, optional sty:tone (e.g. sty:Danger for a destructive action), c:disabled. Choosing it closes its menu; anything else it does is its own beh:Reaction (per instance or per class), applied in the same delta. |
| `Pressable` | Mixin: activating the component flips its c:pressed (a toggle button). |
| `Setter` | Mixin: activating the component sets c:property of the node it c:controls to its c:value (a menu item that records a choice, a button that switches a mode). |
| `Toggle` | A pressed / not pressed button for a boolean property (c:property of c:controls). |
| `Toolbar` | A row of controls (c:children: fields, choices, switches, buttons, a spacer) that wraps on narrow widths: role=toolbar, named by c:label. An inspector's filter bar is one. |
| `Unsetter` | Mixin: activating the component removes c:property of the node it c:controls (the counterpart of c:Setter: a Deselect, a Clear). |

| `SourceText` | A text a graph was loaded from, as data: its c:path, its c:language and the c:text itself (comments and layout included). The host records the ones worth showing (an example's file). |
| `SourceView` | A source text (c:of, a c:SourceText) shown verbatim and syntax-colored, under its c:path, with line numbers. c:label names it (default: the path). The toggles in its header fill the window with it, or the screen (fs:Fullscreenable): a long file read at the width of the screen. |
| `StepInView` | The host reports which rendered step of a walkthrough is being read (it crossed the reading line while scrolling). Not recorded. |
| `Text` | Running text: c:label is the text, or c:children an inline sequence of strings and components (links, kbd, code). Set in the type scale by sty:textStyle (default body) and colored by sty:tone (its --tone-text). A paragraph, or a span when c:inline is true. |
| `Walkthrough` | An explanation in steps beside a diagram of what it mentions: c:label (a title), c:note (a lead), c:steps (an rdf:List of c:WalkthroughStep), and optionally c:sourceView, the source it explains. The diagram shows every resource a step's c:Mention mentions, plus c:diagramIncludes, minus c:diagramExcludes, and the links among them; it stays beside the steps while they scroll (they stack when narrow). The step being read (c:current, by default the first) focuses its mentions in the diagram, and arrows (c:Connector s) join each of its mentions to its node. The toggles on the diagram fill the window, or the screen, with the diagram (fs:Fullscreenable, fs:part): a large graph at a size it can be read at. |
| `WalkthroughStep` | One step of a c:Walkthrough: running text (c:children: strings and inline components, among them c:Mention s) under an optional title (rdfs:label). Focusable; focusing it makes it the current step. |
## Windows

| Term | Contract |
| --- | --- |
| `Desktop` | A surface for windows that is not part of any page: it places the windows it c:hosts. Components that open windows say where with c:windowsOn, so a detached view survives navigation between pages that would hide its origin. Raisable frames go in one stacking layer, ordered by their c:z; other hosted overlays (dialogs, toasts) stay above it. |
| `DesktopLayout` | Supporting vocabulary or internal term; inspect its ontology before use. |
| `Dockable` | Mixin: c:attachedTo an edge of the viewport, the frame fills that edge (a side panel, a top or bottom bar). Dropping it with the pointer within c:snapDistance of an edge attaches it there; dragging it away, or a control marked c:undocks, floats it again where it was. A release counts where its momentum would carry it (c:throwTime), so a frame thrown at an edge docks there too. |
| `Draggable` | Mixin: dragging the component's handle (an element marked data-sem-gesture="move") moves it; one beh:Move event commits c:x and c:y. |
| `Edge` | Supporting vocabulary or internal term; inspect its ontology before use. |
| `Frame` | A floating container: a title bar (c:title) over a body (c:body), placed on a c:Desktop. Every frame moves and comes to the front; its other capabilities are its classes'. |
| `Maximizable` | Mixin: a control marked c:maximizes sets c:windowState c:Maximized: the frame fills the viewport (less the edge a docked taskbar keeps), and c:restores returns it to its place (floating or docked). The frames on its desktop behind it (a lower c:z, or the same and placed before it) cannot be seen, so they are not shown: hidden, their bodies parked, until they come in front of it or it is restored. |
| `Minimizable` | Mixin: a control marked c:minimizes sets c:windowState c:Minimized. A minimized frame is hidden (its content is parked, not dropped); its desktop's c:Taskbar shows it and restores it. |
| `Palette` | A small floating tool frame: a slim title strip, no minimize or maximize. It moves, comes to the front, docks to an edge and closes; an instance that is also c:Resizable gets a grip. |
| `PointerDown` | A pointer was pressed inside the component. |
| `Raisable` | Mixin: pressing anywhere in it (c:PointerDown) brings it in front of the other frames on its desktop. The desktop names its c:topmost frame and each frame keeps the c:z it was raised to (one more than the highest on the desktop), so stacking is graph state and raising changes two frames' worth of triples. |
| `Resizable` | Mixin: dragging its grip (data-sem-gesture="resize") resizes it; one beh:Resize event commits c:width and c:height. |
| `Restorable` | Mixin: has a c:windowState; a control marked c:restores sets it back to c:Normal. |
| `Taskbar` | The open frames of a desktop (c:of), one entry each with its state's symbol and its title. Activating an entry restores a minimized frame, brings another to the front, and minimizes the frame already in front (if it is c:Minimizable). Hidden while no frame is open. Hosted on the desktop itself, it is there on every page. An instance that is also c:Draggable has a grip (dragged, or moved with the arrow keys: c:x, c:y), and one that is also c:Dockable docks to the edge it is thrown at (c:attachedTo): along the top or bottom it lies across, along the start or end it stands upright, and the page keeps that edge clear. |
| `Window` | A floating window with every capability: move, resize, raise, minimize, maximize, dock to an edge, close. |
| `WindowState` | Supporting vocabulary or internal term; inspect its ontology before use. |
