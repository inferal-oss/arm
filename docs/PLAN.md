# Implementation plan

The complete scope remains [SPEC.md](../SPEC.md). A stage is complete only when its behavior has been reviewed and its relevant checks pass; unsupported platform and hardware checks stay explicit.

| Stage | State | Remaining work |
| --- | --- | --- |
| Backend and CLI foundation | Implemented | Command-specific help, start/stop shortcuts, intermixed flags, positional storage sizes and default loopback ports are validated. Maintain lifecycle, admission, SQLite, process supervision, WebSocket and recovery checks. |
| Human CLI presentation | Implemented | Terminal-aware fields/resource tables, explanations and ANSI colors; explicit/piped JSON and child-output separation. Install/uninstall preview and default-no confirmation, noninteractive --yes, identity/content/manifest revalidation and real PTY checks exist. Maintain presentation and interruption safeguards as commands grow. |
| Agent integration | Native delivery and polling fallback validated | Installed instructions link to the offline arm agents operating guide. Recipient inboxes, bounded long polling, cursor-based watch/reconnect, explicit receipt/acknowledgement, resumable instruction upgrades and automatic usage-warning routing exist. Generated warnings reached real Codex/Claude sessions. Native policy delivery has one bounded attempt per warning plus the durable polling fallback; richer retry policy and agent-specific background/subagent forwarding remain. Active Claude injection remains unsupported. |
| Host observation and filesystem accounting | Partial | Host monitoring adds native CPU/core, memory/swap, per-device disk/network intervals, cached filesystem space, bounded ephemeral history and shared WebSocket snapshots/streaming. Host memory, filesystem blocks, APFS container UUIDs, read-only sparse/hard-link/clone inspection and captured supervised-group CPU/memory samples exist. Stronger containment/accounting of exited and escaped descendants, exclusive/reclaimable extents and pressure-aware admission remain. |
| Managed storage | Partial, initial lifecycle validated | Dedicated storage leases, explicit supervised consumers, retained outputs, creation-time identity checks, bounded cleanup, retry/handoff and conservative unresolved accounting exist. Unprivileged Linux cleanup can be blocked by inaccessible same-user services; capability and privileged-observer policy need work. Configurable roots, adoption/shared caches, remount identity resolution and reclaim verification remain. |
| Resource providers | Partial, initial ports integrated | Atomic port admission, held/cooperative modes, socket activation, dedicated parent/consumer leases, conservative revocation/restart, protected backend allocation and native inventory exist. Cross-namespace reconciliation, richer socket-option observations, GPU inventory/capabilities and network budgets/attribution remain. |
| Custom coordination pools | Local implementation validated | Agent-created host/global counted pools, transactional set/adjust and session-attributed journal, ordinary claims and queues, exact int64 responses, visible deficits, guarded metadata/drain/resume/delete and recovery exist. Global scope currently uses one local authority; remote transport, authority partition/failover checks, external fencing and web/TUI controls remain. |
| Workload knowledge | Partial | Cargo jobs and attached managed target settings have real build tests. Add complete configuration/alias resolution, embedded indexed cards and code-based adapters for persistent services and other workloads. |
| Policy and enforcement | Partial, opt-in supervised policy validated | Scoped CPU/memory incidents, resolved per-run warn/revoke policy, atomic warning inbox/outbox, grace periods, observation-gap handling and owned-group revocation exist. Kernel limits, containment/accounting of escaped descendants, unsupervised/provider incidents, profile/host policy configuration, owner/nested budgets, queue explanations and early-release credit records remain. |
| Agentic lease reviews | Planned | Optional heartbeats asking whether leases are still needed and why; contention-aware cadence, per-agent coalescing and invocation budgets, exact-session/polling delivery, durable review/reply state and UI visibility. Replies request ordinary authorized actions; silence and acknowledgement never extend deadlines or prove compliance. |
| Operator interfaces | Clients planned; monitor backend implemented | Web and TUI through the shared WebSocket backend; resources, consumers and reasons, leases, messages, incidents and actions. Both get a btop-inspired Monitor tab for host CPU, memory/swap, filesystem space and disk I/O, network rates and supported GPU metrics, with bounded histories and explicit stale/unavailable readings. |
| Operations | Partial | Configuration and policy snapshots (including journalled built-in budget changes), native services, drain/cancel uninstall, retention, migration and degraded-state handling. |
| Cross-platform acceptance | Partial | macOS race/native APFS tests, actual Linux arm64 container tests and OrbStack SSH acceptance passed, including inbox reconnect checks. Expand filesystem, resource, native services, hardware, failure and recovery tests; native amd64 remains. |
| Remote hosts | Planned, after local correctness | Authenticated host transport, registration/selection, remote execution, stale inventory and partition recovery. |

The current implementation is an initial local milestone, not completion of the complete specification. See [IMPLEMENTATION.md](IMPLEMENTATION.md) for actual capabilities and [VALIDATION.md](VALIDATION.md) for dated evidence.
