# Implementation plan

The complete scope remains [SPEC.md](../SPEC.md). A stage is complete only when its behavior has been reviewed and its relevant checks pass; unsupported platform and hardware checks stay explicit.

| Stage | State | Remaining work |
| --- | --- | --- |
| Backend and CLI foundation | Implemented | Command-specific help, start/stop shortcuts, intermixed flags, positional storage sizes and default loopback ports are validated. Maintain lifecycle, admission, SQLite, process supervision, WebSocket and recovery checks. |
| Human CLI presentation | Implemented | Terminal-aware fields/resource tables, explanations and ANSI colors; explicit/piped JSON and child-output separation. Install/uninstall exact line/byte/existence/hash previews, colorized --diff, verified private originals/metadata backups, default-no confirmation, noninteractive --yes, identity/content/manifest revalidation and real PTY checks exist. Maintain presentation and interruption safeguards as commands grow. |
| Agent integration | Native delivery and polling fallback validated | Installed instructions link to the offline arm agents operating guide. Recipient inboxes, bounded long polling, cursor-based watch/reconnect, explicit receipt/acknowledgement, resumable instruction upgrades and automatic usage-warning routing exist. Generated warnings reached real Codex/Claude sessions. Native policy delivery has one bounded attempt per warning plus the durable polling fallback; richer retry policy and agent-specific background/subagent forwarding remain. Active Claude injection remains unsupported. |
| Host observation and filesystem accounting | Partial | Host monitoring adds native CPU/core, memory/swap, per-device disk/network intervals, cached filesystem space, bounded ephemeral history and shared WebSocket snapshots/streaming. Host memory, filesystem blocks, APFS container UUIDs, read-only sparse/hard-link/clone inspection and captured supervised-group CPU/memory samples exist. Stronger containment/accounting of exited and escaped descendants, exclusive/reclaimable extents and pressure-aware admission remain. |
| Managed storage | Partial, initial lifecycle validated | Dedicated storage leases, explicit supervised consumers, retained outputs, creation-time identity checks, bounded cleanup, retry/handoff and conservative unresolved accounting exist. Unprivileged Linux cleanup can be blocked by inaccessible same-user services; capability and privileged-observer policy need work. Configurable roots, adoption/shared caches, remount identity resolution and reclaim verification remain. |
| Resource providers | Partial, initial ports integrated | Atomic port admission, held/cooperative modes, socket activation, dedicated parent/consumer leases, conservative revocation/restart, protected backend allocation and native inventory exist. Cross-namespace reconciliation, richer socket-option observations, GPU inventory/capabilities and network budgets/attribution remain. |
| Custom coordination pools | Local implementation validated | Agent-created host/global counted pools, transactional set/adjust and session-attributed journal, ordinary claims and queues, exact int64 responses, visible deficits, guarded metadata/drain/resume/delete and recovery exist. Global scope currently uses one local authority; remote transport, authority partition/failover checks, external fencing and web/TUI controls remain. |
| Workload knowledge | Partial | Cargo jobs and attached managed target settings have real build tests. Add complete configuration/alias resolution, embedded indexed cards and code-based adapters for persistent services and other workloads. |
| Policy and enforcement | Partial, opt-in supervised policy validated | Scoped CPU/memory incidents, resolved per-run warn/revoke policy, atomic warning inbox/outbox, grace periods, observation-gap handling and owned-group revocation exist. Kernel limits, containment/accounting of escaped descendants, unsupervised/provider incidents, profile/host policy configuration, owner/nested budgets, queue explanations and early-release credit records remain. |
| Agentic lease reviews | Planned | Optional heartbeats asking whether leases are still needed and why; contention-aware cadence, per-agent coalescing and invocation budgets, exact-session/polling delivery, durable review/reply state and UI visibility. Replies request ordinary authorized actions; silence and acknowledgement never extend deadlines or prove compliance. |
| Operator interfaces | Initial observation web client; rendered acceptance pending | The initial read-only web client uses shared WebSocket requests/events/telemetry for Monitor, Resources with consumers/reasons, Leases, Messages, Activity and Host. Browser automation is disabled, so real layout/navigation/narrow-size/reconnect acceptance remains pending. Guarded lease actions and exact-recipient/idempotent sends are available in the backend; CLI operator sends use them. Add browser controls, storage/incident views, pool journals and equivalent TUI operations. Both get a btop-inspired Monitor tab for host CPU, memory/swap, filesystem space and disk I/O, network rates and supported GPU metrics, with bounded histories and explicit stale/unavailable readings. |
| Operations | Partial | Configuration and policy snapshots (including journalled built-in budget changes), native services, drain/cancel uninstall, backup/history retention and safe restoration, migration and degraded-state handling. |
| Cross-platform acceptance | Partial | macOS race/native APFS tests, actual Linux arm64 container tests and OrbStack SSH acceptance passed, including inbox reconnect checks. Expand filesystem, resource, native services, hardware, failure and recovery tests; native amd64 remains. |
| Remote hosts | Planned, after local correctness | Authenticated host transport, registration/selection, remote execution, stale inventory and partition recovery. |

## Current operator experience work

The following requests are part of the active scope, not a claim of completed support. Keep the web panel and terminal dashboard aligned in layout, labels and operation semantics.

| Item | Current state / acceptance remaining |
| --- | --- |
| Safe operator operations | Implemented and validated: revision-guarded lease actions, durable exact-recipient/idempotent message sends, CLI send/broadcast retry keys and linked replies. Browser controls still need to use these operations and receive interface acceptance. |
| Structured JSON inspection | In progress: expandable/collapsible object and array trees replace raw lease/event/host JSON blocks in the worktree. Preserve exact integer values, keyboard access and bounded/lazy rendering; complete browser acceptance. |
| Dashboard readability and visual quality | Requested: improve hierarchy, spacing, typography, density and empty/connection states. Remove collector scopes, syscall names and long accounting caveats from cards; put short human explanations and optional technical details behind accessible (?) popups. Keep unavailable/stale readings explicit. |
| Persistent live activity feed | Requested: show lease/message events on every view, always accessible within the viewport. Use a side feed on wide screens and a compact expandable feed on narrow screens. Preserve navigation/focus and bound retained entries. |
| Dashboard operator messaging | Requested: composer, exact registered-agent selection, broadcasts, linked replies and delivery/receipt outcomes. Review recipients/method/body before sending; preserve request/key across uncertain outcomes and never silently repeat native delivery. |
| Dashboard lease operations | Requested: renew/release/cancel/reconcile and supported storage actions from detail views, with concrete consequences/ownership uncertainty and revision guards. A declined confirmation must not mutate state. |
| Navigation history | Requested: use URL history for view/detail state; reload and browser Back/Forward restore the same place. Bootstrap fragments must still be removed without storing credentials in navigation history. |
| Browser selection | Requested syntax: `arm dashboard [BROWSER]`, e.g. `arm dashboard Safari`. On macOS support application names/paths using open -a; support executable names found on PATH. Keep explicit/piped JSON and --no-open from launching a browser. |
| Terminal dashboard | Requested entry point: `arm dashboard terminal`. Follow the same web layout: header, view order, main workspace, side feed, labels, detail/actions and compact layout. Use the same backend protocol; verify real terminal keyboard/resize/reconnect behavior. This command is not yet implemented. |
| Live memory pool | Requested correction: memory admission must follow current host availability rather than assume a fixed 8 GiB pool. Capacity is a moving target and may fall below existing claims. Preserve obligations, expose shortfalls and block unsupported new grants/renewals. Define and validate conservative macOS/Linux availability, freshness/failure policy, optional operator ceiling and existing-usage accounting; avoid presenting free pages as complete reclaimable memory or silently subtracting the same allocation twice. The current fixed default is still implemented until this work lands. |
| Bulk lease operations | Requested: `arm release --all` and `arm cancel --all` for the selected local authority. Reuse ordinary ownership, supervision and storage rules; distinguish release/cancel outcomes, preserve unresolved obligations, report per-lease partial failures, and reject combining an ID with --all. Share lifecycle orchestration with force/wait shutdown rather than bypassing provider safeguards. These flags are not yet implemented. |
| Forced and waiting shutdown | Requested: `arm stop --force` ends leases and cancels ARM-owned supervised work before shutdown; `arm stop --wait` drains/waits for outstanding leases; `arm stop --wait --timeout SECONDS` force-releases remaining work when the timeout expires. Preserve ownership checks and durable outcomes; report retained data/unverified reclamation. Cover aliases, signals/disconnects, deadlines, active work and recovery. These flags are not yet implemented. |

Rendered browser acceptance remains pending because this task's browser tool reports local browser use disabled. This does not block backend, CLI or TUI work; it must not be treated as successful visual acceptance. The complete specification and broader remaining stages above remain in scope.

The current implementation is an initial local milestone, not completion of the complete specification. See [IMPLEMENTATION.md](IMPLEMENTATION.md) for actual capabilities and [VALIDATION.md](VALIDATION.md) for dated evidence.
