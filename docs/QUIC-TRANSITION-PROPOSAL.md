# QUIC transition for ARM mesh execution and sync

**Research proposal, October 25, 2026. No production QUIC path is implemented or authorized for this phase.** The target architecture retains verified SSH for `arm mesh connect` bootstrap and installation, then establishes pinned QUIC sessions for ARM control, execution, terminal and rsync traffic. The operator subsequently deferred QUIC implementation to research only while the main integration work reviews nonresearch sync, routed SSH and Kubernetes portfolios. The earlier QUIC-first gate therefore does **not** block those portfolios now. This document records a future transition plan and acceptance gate; it creates no listener, grant migration, branch or worktree.

## Decision and scope

Use `github.com/quic-go/quic-go` **v0.63.0** with the project's Go 1.27.3 toolchain for a native, CGo-free QUIC v1 transport. It is a maintained pure-Go implementation with bidirectional streams, connection/stream flow control, TLS 1.3 and explicit 0-RTT controls. Its September 2026 release supports Go 1.27. The isolated probe below compiled for macOS/Linux on arm64/amd64 and ran on macOS arm64. This is feasibility evidence, not portable or product acceptance. Pin the dependency and checksums in the main module only in the reviewed base implementation cut. [quic-go releases](https://github.com/quic-go/quic-go/releases), [quic-go API](https://pkg.go.dev/github.com/quic-go/quic-go@v0.63.0), [release policy](https://github.com/quic-go/quic-go#release-policy).

There are **two distinct changes**:

* **A, compatibility carrier:** put the present `sshservice.Server.Serve` / OpenSSH wire session on one QUIC bidirectional stream, adapting it to `net.Conn`. This can preserve current OpenSSH behavior and serve as an integration oracle, but the application still speaks SSH, including SSH authentication and channel messages. A alone does **not** complete the requested replacement.
* **B, target application protocol:** after SSH-assisted enrollment, use QUIC's mutually authenticated connection and separate bounded streams for closed ARM control, one admitted execution, stdin/stdout/stderr, PTY/resize/signals/exit, exact-key lookup/seal and standard rsync bytes. This replaces the embedded SSH wire machinery while retaining the existing command, account, grant, resource and receipt semantics. B is the base transition gate. Keep A as an explicitly identified compatibility adapter while system OpenSSH interoperability is needed; do not silently claim that native OpenSSH understands ARM's QUIC protocol.

The current `arm ssh` CLI command and its flags/output/exit and PTY behavior should continue through a native client in B. Verified system OpenSSH still bootstraps machines without ARM. If arbitrary external `ssh`/ProxyCommand clients must reach an already enrolled node, retain a tightly scoped local SSH compatibility gateway into the same destination admission API or the A stream, with one-use authentication and the same exact operation key. Do not expose a general SSH or port-forward service. Keep the existing OpenSSH blackbox as a regression gate until this explicit choice is implemented. `rsyncengine.Run` takes `io.ReadWriteCloser`, so its standard protocol-27 exchange can run on a QUIC stream without changing the rsync algorithm, wire format, or dependence policy.

## Native QUIC contract

**Bootstrap and network.** Retain the existing verified SSH host/account check for installation, first enrollment and recovery on a host without ARM. The operator reviews an exact node identity/certificate pin, UDP endpoint and port, account, host key where legacy SSH is involved, destination rights and resource limits before enabling a QUIC listener. A reviewed direct endpoint is a locator, never permission. Use a configured literal address, no wildcard/public listener by default, no arbitrary remote IP/port in stream requests, no public NodePort or Kubernetes service exposure as a connectivity workaround. Establish reachability explicitly; UDP may be filtered by firewall/NAT and QUIC does not itself provide rendezvous, hole punching or TURN. IPv4/IPv6, MTU, idle timeout, NAT rebinding and connection migration need real network tests. A changed path cannot change the pinned peer, scope or operation key; close if endpoint policy forbids the new address. [RFC 9000](https://www.rfc-editor.org/rfc/rfc9000.html), [QUIC applicability](https://www.rfc-editor.org/rfc/rfc9308.html).

**Authentication and replay.** Use TLS 1.3 with explicit trust roots, normal certificate purpose/SAN/time checks and exact peer DER/SPKI pins bound to stable host ID and enrollment revision. Use a distinct `arm.mesh.quic.v1` ALPN and authenticated versioned application hello. Require client certificates, verify the original source at the final destination, and bind workspace/route ID/path/class, source/final pins, account/service/grant revision, key and expiry in an endpoint control digest. Disable session tickets/resumption initially and use `Dial`, never `DialEarly`; set `Allow0RTT=false`. Execution, seal, grant and file operations must never be accepted in 0-RTT even if resumption is introduced later. QUIC connection IDs, addresses and route headers are not authority. Preserve the existing one-use ephemeral Ed25519 invocation key and source-intent public-key commitment: B should prove possession with a signed, destination-challenged operation/stream digest after mTLS, then consume it exactly once under the same durable key. The SSH host key remains pinned for bootstrap/A/OpenSSH compatibility; removing that pin from a B operation would change an existing reviewed binding and needs explicit scheme review. A QUIC client certificate alone cannot authorize repeat executions. [RFC 9001 replay guidance](https://www.rfc-editor.org/rfc/rfc9001.html#section-9.2), [quic-go client/resumption](https://quic-go.net/docs/quic/client/).

**Closed stream vocabulary.** Reserve a small control/settlement capacity distinct from data streams. A connection can carry multiple operations only when each has independent source intent, destination admission, limits and key; an operation has one exec request and its fixed stream IDs. Define canonical length-prefixed typed frames with strict version/field/size validation, no generic RPC, remote URL/port, SFTP or SSH port-forward. Exec frames cover command/shell kind and digest, bounded env/CWD, optional PTY term/modes/window, resize, signal, stdin EOF, separated stdout/stderr, terminal exit status/signal and an authenticated final operation receipt. An rsync class carries only its fixed worker/control prelude plus raw ordered protocol-27 duplex bytes. Every file endpoint independently checks roots and receive policy. QUIC stream `Close` half-closes its write side; cancellation must call both `CancelRead` and `CancelWrite`, close the connection when ownership requires it, and join producer, consumer and destination process callbacks before lease settlement. Frame, bytes, streams, memory, CPU, idle and lifetime budgets remain explicit and charged to source, destination and each relay. QUIC's flow control bounds buffered data but does not replace ARM accounting, pacing or a reserved control slot. Cross-stream head-of-line blocking is reduced, while streams on one connection still share congestion control and connection-wide flow control. [quic-go streams](https://quic-go.net/docs/quic/streams/), [flow control](https://quic-go.net/docs/quic/flowcontrol/).

**Unknown outcomes and revocation.** Commit the source key/intent before any effect-bearing QUIC frame. At the destination, revalidate current exact source grant, account, resource admission, service/enrollment revision and operation digest immediately before execution or staging. A lost ACK, stream reset, connection migration or relay failure is **unknown** once effect-bearing bytes might have arrived. Only read-only exact-key lookup and an independently durable nonexecution seal can settle it; never retry with a fresh key automatically. A current local deny closes new and live streams, and all transport/worker owners join before reporting reclaimed resources. Relayed membership freshness stays within the approved 60-second bound; a partition can delay remote revocation within that bound and must be shown honestly.

**Mesh routing.** Reuse the approved graph/path, existing exact original-source destination `ssh-exec` plus `lease-own` grant, and separate per-hop `ssh-relay` opt-in for the **same `ssh` operation class and ceilings**. Change the carrier implementation and its versioned route record, not the grant's execution meaning. `sync` remains reserved until its endpoint worker, roots and receive policies pass separate review. The destination grant is for the cryptographically verified original source, never the last hop. For a fully UDP route, relays forward only bounded packets for the immutable next directly paired node and fixed route/session ID; the end-to-end QUIC handshake stays between source and destination. A relay can observe metadata, timing and length and can drop packets, but cannot decrypt application payload, lend its execution grant or choose a caller supplied socket destination. Existing WebSocket/TCP hops can carry **framed QUIC datagrams** as an explicit compatibility route; this remains QUIC's authenticated end-to-end protocol but incurs outer TCP head-of-line blocking and must not claim native UDP performance. Prevent loops/replay, cap hops/packets/bytes/rate/lifetime, and avoid unbounded buffering when a downstream route stalls. Preserve exact-key read-only lookup across a newly approved path, not automatic execution replay. Review the new UDP parsing/forwarding and authenticated packet-to-route binding before enabling it; that review need not invent a broader grant.

**Kubernetes.** `kubectl`/client-go port-forward is TCP only, including the WebSocket-over-SPDY fallback in the unmerged adapter. A native UDP `quic.Listen` Pod endpoint cannot be reached through the current Pod port-forward. The feasible no-exposure option is a **fixed, length-framed QUIC packet carrier** over that already reviewed, UID-bound TCP forward, with a `net.PacketConn` adapter on each end and strict packet/stream bounds; it needs a separate implementation and authenticated integration test, and has TCP head-of-line and congestion interaction. Alternatively use the same closed ARM application protocol over a pinned TLS/TCP forward, explicitly labeled a transport exception rather than QUIC. Neither option opens a NodePort, assumes UDP port-forward, or weakens Pod/ARM identity. The base gate must choose and test one supported Kubernetes path or explicitly keep the existing SSH/TCP bootstrap path available without claiming Kubernetes QUIC support. [Kubernetes port-forward TCP limitation](https://kubernetes.io/docs/tasks/access-application-cluster/port-forward-access-application-cluster/), [Kubernetes WebSocket streaming](https://kubernetes.io/blog/2024/08/20/websockets-transition/).

**Mac VNC.** Standard RFB can use a separately approved bounded stream once a real OS-service and viewer identity boundary passes. High Performance UDP needs a separately typed session-bound datagram path and native two-Mac proof; QUIC DATAGRAM is an extension with unreliable delivery, not a substitute for Apple's auth/session semantics. Framing those datagrams over a TCP relay may break latency goals. Do not fold VNC into the existing SSH execution class, attach to Screen Sharing, or claim live capture from this transition. [QUIC DATAGRAM](https://quic-go.net/docs/quic/datagrams/), [existing VNC research](MESH-VNC-PROPOSAL.md).

## Isolated evidence and limits

`internal/quicprobe` is a separate, untracked Go module (`go.mod` and checksum-verified `go.sum` are private to it). Native macOS arm64 `go test -p 1 -race -count=1 -timeout=30s -v ./...` and `go vet -p 1 ./...` passed four tests with Go 1.27.3 / quic-go v0.63.0: ephemeral pinned mutual-TLS identities, distinct ALPN, wrong server certificate rejection, a wrong client identity that did not reach server application accept, an authenticated bidirectional stream, a 16-KiB unread-stream flow window that stopped an 8-MiB write at 16,384 bytes with a deadline, cancellation and joined server worker, and a 65,536-byte verified staging exchange using the **actual** `internal/rsyncengine.Run` client/server roles. A packet wrapper captured 20 client and five server outbound UDP packets in the final run; the known dummy command/file marker was absent from all recorded packet bytes. This is a limited ciphertext sanity check, not a cryptographic proof or a throughput benchmark. The wrapper elicited quic-go's UDP receive-buffer warning; production should use a native UDP socket and separately measured memory/packet telemetry. The wrong-client test exposed an important API boundary: client `Dial` returned success although the destination never admitted its connection to the server application. Only a server-verified admission/ready response can establish that the destination accepted the source; the client must not dispatch an effect-bearing frame merely from `Dial` success. The test uses dummy bytes and ephemeral identities, touches no ARM backend or real endpoint, and creates no public listener.

No mesh relay, real account/resource admission, SSH child, native Linux **execution**, real rsync binary, Kubernetes Pod, VNC session, firewall/NAT or revocation was exercised. The direct rsync probe confirms protocol compatibility with the Go engine, not full staged publication or reconciliation. There is no same-engine current `meshstream` throughput comparison yet; the current carrier requires a real pinned mesh/lease fixture, so no relative performance conclusion is drawn. The test process exited zero and owned its disposable sockets/workers. `CGO_ENABLED=0 go test -c` produced Mach-O arm64/amd64 and ELF arm64/amd64 binaries; cross-compiled binaries alone are not native Linux evidence.

## Ordered implementation cuts and acceptance gate

1. **When QUIC implementation resumes, freeze its baseline on the selected integration worktree.** Record HEAD/status and current direct/routed SSH, source-history, rsync and lifecycle gates. Keep SSH bootstrap and independently integrated portfolios intact. Review the exact new UDP listener/endpoint and transport authentication scheme before exposing it.
2. **Private transport owner.** Add a pinned QUIC dependency, typed connection/stream wrapper and deadline/cancel/join accounting with direct loopback and real native network tests. Allow only literal reviewed peer endpoints, pinned mTLS, no resumption/0-RTT, and bounded streams/bytes/memory/CPU. A may be used as a temporary parity oracle; do not mark transition complete here.
3. **Factor destination semantics out of SSH.** Move current admission, process lifecycle, exact lookup/seal and receipt code behind a transport-independent service used by old SSH and B. Add typed native QUIC execution/PTY/rsync frames and prove possession of the existing one-use invocation key bound to the existing durable operation key. Do not change direct/routed `ssh-exec`, `lease-own`, account or resource grant meaning implicitly. Preserve exact original worker joins and refusal of unsupported channels/attachments.
4. **Route and bootstrap.** Keep verified SSH install/enrollment; add a separately reviewed UDP endpoint and typed multi-hop QUIC packet route under the existing `ssh-relay` class and original-source destination grant, with identical ceilings/freshness. Retain a bounded framed-carrier fallback where UDP is unavailable. Integrate `arm ssh` and the fixed rsync engine; maintain deliberate OpenSSH compatibility and current recovery commands.
5. **Future QUIC acceptance gate, before claiming its base transition complete:** all existing direct command/shell/PTY/resize/stdin/stdout/stderr/exit/signal/cancel/expiry/Stop/resource/history tests pass; system OpenSSH bootstrap and explicitly chosen compatibility workflow still pass; actual authenticated native macOS and Linux direct **and B→A→C unreachable-endpoint** sessions pass; exact account/pin/grant, original-source relay denial, revocation during live work, stale membership, duplicate/replayed control, partition and lost-result no-replay/lookup/seal cases pass; source intent precedes dispatch and destination receipts/worker joins survive failures; standard rsync push/pull/interoperability against real rsync binaries and staged hashes pass over QUIC; Kubernetes's chosen forward carrier is tested without UDP exposure; CGo-free four-target packaging builds and actual supported OS execution pass. Measure throughput/latency/CPU/memory on encrypted links against current carrier under the same workload, including slow consumer and loss. Record all exits, retained unknown obligations and limitations in `docs/VALIDATION.md`. A green synthetic loopback probe alone is insufficient.
6. **Independent portfolios now.** The main integration task may review and integrate sync reconciliation/filesystem, pressure accounting, routed SSH, Kubernetes and Mac VNC independently of this deferred QUIC research. Do not copy/reset/delete their work as part of this proposal. When QUIC resumes, preserve the then-current baseline and its accepted portfolio behavior through the same gate.

**Minimal future scheme review, not a runtime approval request now:** retain current `ssh-exec` plus `lease-own` at the destination and `ssh-relay` on each hop for the same source, operation class, account, TTL/resources, pins and original-key rules. Review only the new literal UDP endpoint/listener, QUIC mTLS/ALPN and server-ready handshake, reuse of the existing one-use signer as a signed QUIC invocation, and typed bounded packet forwarding to an exact paired next hop. Ask for a new grant only if implementation demonstrably widens an operation, target, file root, relay capability or identity binding beyond that approved scheme.
