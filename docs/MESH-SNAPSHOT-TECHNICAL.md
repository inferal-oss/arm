# Snapshot generation technical contract — S approved, implementation pending

The operator approved S only on October 25, 2026, and subsequently approved the explicit [verified-copy policy and publication-check boundary](MESH-SNAPSHOT-VERIFIED-COPY.md). That amendment adds a separately selected nondestructive creation policy and supersedes the requirements below for source idleness and continuous authority through a blocking publication commit when that policy is selected. It preserves strict idle mode, all destructive cleanup checks and required acceptance gates. F remains a proposal with no authority to enable delegated delivery. Neither mode has completed runtime acceptance.

## Creation and publication transaction

1. Initial S keeps source and new destination allocations under the same origin host/account/provider; there is no caller-selected export/adoption destination or cross-host copy in this initial scope. Cross-host consumers remain separate staged admissions. `snapshot preview` conceptually resolves an exact host/owner/source storage lease+revision and explicit file selections. Resolve all source paths with existing current native access/identity checks. Require idle managed source for initial scope; no application-wide atomicity promise across changing build outputs. Display selected bytes, full-copy disk requirement/uncertainty, mode S/F policy, retained recipients, TTL and required resources. CLI names here are proposed, not commands that exist.
2. Before side effects, one authority transaction reserves the destination managed storage lease and copy/publication CPU/memory/FD/quota, pins the source dependency and records the immutable copy intent/key/digest plus the planned managed allocation locator. Any later cross-host creation/replication needs its own explicit source/destination review and staged lifecycle; initial S does not enable it or promise multi-host atomic capacity. Creation of a new allocation necessarily precedes observing its inode: record that exact owned allocation identity durably before any payload copy, with partial/unknown allocation or marker creation retained as a charged duty. Do not pretend a future inode was known before mkdir. Snapshot creation and publication each require current explicit local policy/directional authority for this mode, denied by default; strict-only publication/observation grants never imply it. Same key+same intent is lookup; conflict refuses.
3. A bounded owned copy worker writes only into that new private allocation. Prefer ordinary bounded copy initially. A clone is permitted only if actual capability is verified and its handling of metadata/ACLs is normalized safely; it never shares an inode/hard link. Source before/after identities and full content hashes must agree with the reviewed selection. No source directory recursion/globs/symlink following/device copy. Per-file clone atomicity is not a multi-file point-in-time snapshot; require the source idle and fail its final complete version comparison if it changes.
4. Keep current source entitlement/native checks during creation and revalidate the complete original source proof before the publication commit. Sync data and required directories, close writer handles, verify the entire destination against a canonical manifest and exact native identity, then persist prepared state. Close or sync errors remain duties. Publish is a second exact generation/revision/hash approval. A crash before a trustworthy final commit exposes no generation; lost commit replies are recovered by original key.
5. Publication records source provenance, destination storage identity/lease, mode/policy hash, content/metadata manifest, copy method and actual sealing capability, owner/session/reason, budgets, retention, worker/native closure and audit sequence. Metadata exposed to consumers is the immutable manifest's read-only mapping; unsupported xattrs/ACLs/locks are explicit. The original source can be unpinned only after (a) exact publication has committed or the unpublished intent has been explicitly canceled, and (b) its original copy/native workers and source descriptors have actually joined/closed. Original cleanup remains its own ordinary storage decision. Source expiry/revoke before publication immediately prevents publish and starts exact cancellation/settlement; a dependency pin never renews source authority. Destination staged data remains charged until its separate cleanup is verified.

A preview creates no retained source pin or destination promise; any expensive review scan needs its own bounded admitted work. After the first durable prepared state, publication review has at most five minutes, shortened by the source entitlement, copy intent, destination retention and grant/certificate deadlines. The first validated elapsed anchor is immutable; polling, default-no, lost replies, source renewal and restart never extend it. Default-no/abandonment reaches ordinary cancellation at that deadline. A lost elapsed owner or uncertain clock after restart blocks publication and reconciles/cancels the exact prior operation, rather than rearming five minutes. Unknown native completion can keep visible charges/pins, but cannot keep permission to publish. Only a fresh explicit reviewed operation can create a new budget; it cannot erase the older duty.

Published-generation data is defined by its approved manifest, not by the current source name or ACL. Content chunks must hash before entering an immutable verified buffer; no unhashed bytes escape. Hashing borrowed mutable memory or trusting read-only mode bits is insufficient. An altered stored chunk fails or is replaced only by another copy whose digest matches that **same** generation. Silent mutation/adoption of a new generation is forbidden. The service may retain a verified older chunk after backing-file corruption because it still is the approved original content; record degradation and stop new sessions pending reconciliation rather than substitute data.

Initial S still uses its separately leased durable managed disk generation. A volatile sealed object may only strengthen an additionally accounted runtime cache; it does not replace the destination storage lease, retention or recovery duty.

macOS ordinary copies/APFS clones are **not** described as kernel-sealed. The portable security boundary remains cooperating ARM-owned state, private directories, nonexecutable/read-only exposure, immutable in-process verified chunk buffers and exact authenticated manifests. Arbitrary same-user/root interference is outside strong isolation; integrity failures deny service rather than serving changed bytes. Snapshot mode deliberately changes native-original-path checks; it does not claim those checks were somehow retained or cached.

## Per-delivery authority in S

Use direct pinned TLS1.3 mTLS and exact endpoint/grant revision; no routed discovery membership grants file access. Enrollment changes/revoke disconnect sessions. A new optional grant/policy `snapshot-read` must name the exact generation or locally approved bounded publication policy; strict-only/file observation grants do not imply it. Publication permission and local mount permission remain separate. Authenticate host/account, not a caller-supplied agent label. Tie each transport/opaque handle to source/destination/owners, pair/enrollment, grant revision, consumer lease IDs, generation/manifest/mode/policy, source and consumer boot/session, and unique request sequence.

Before each origin response: check current origin publication/generation/storage lease, active remote consumer admission, current enrollment/grant revision and monotonic remaining lifetime, plus integrity/read bounds. After preparing bytes, repeat current authority and generation/close fence before handing them to transport. Local adapter similarly checks current local consumer/mount lease, expected generation, local grant policy, close/recall state and remaining lifetime immediately before its FUSE response. No per-delivery original-source native path/ACL lookup occurs: that is the approved S change. No origin data protocol opens a caller-specified path outside the generation.

S denies new origin operations immediately after the origin's own revoke/expiry transition and aborts streams. It cannot erase a response already queued/sent or bytes already received. A local synchronous S response arriving after local expiry is discarded. Independent source and consumer accounting survives partitions and lost close replies.

## Optional F: a bounded canonical-chunk credit protocol

F requires a separate explicit `snapshot-delivery` grant/policy at both ends. Initial policy caps: <=250 ms credit lifetime; exactly one canonical manifest chunk per credit (offset aligned to one MiB, full one-MiB length except the shorter final chunk); <=8 simultaneous owned slots and <=8 MiB per consumer; <=32 MiB per consumer authority. Arbitrary offset/length credits are not part of initial F. Each slot covers the pending request, partial data, verification, ready data, pinned responses, ending/unknown work and transport cleanup until actual settlement; no layer returns a slot merely because authority expired or its byte allowance was spent. These are new proposed maxima, not existing permissions. Lower host/operator limits take precedence. At issuance, its deadline is no later than the conservative remaining lifetime of either consumer entitlement, publication/storage retention or certificate/enrollment validity. Later local shortening/revoke fences immediately; an earlier remote shortening/revoke can have only the explicitly approved already-issued tail described below. No credit silently follows a renewal or changed policy.

These are simultaneous occupancy/permission bounds, not an eight-MiB-per-250-ms rate limit. Once prior ownership is actually settled, a fresh source-authorized request can refill a slot at the network's practical rate. All per-consumer/authority memory, transport, FD and work limits still apply. Expiry/recall invalidates delivery authority immediately at its specified cut; still-owned buffers/fetches/response results remain charged and occupy the old slot until their exact close/join is established for every owned reference; internal cache-to-response ownership moves keep the same slot counted. Initial F discards expired/recalled data before reuse; possession alone grants nothing.

A new versioned bounded control exchange binds each credit to: origin+consumer host/account, authenticated connection and both boot/session IDs, exact pair/grant revision, publication+storage+consumer lease IDs and revisions, generation+manifest+policy SHA, file ID/canonical chunk index/derived offset/exact tail-aware length and chunk digest, operation/request nonce+strictly increasing serial, maximum byte disclosure, remaining lifetime and recall epoch. The credit is accepted only as a frame received on that exact authenticated pinned channel, stored in the trusted adapter's bounded runtime memory. It is never accepted from a file, browser request, another channel or restarted process; no portable signed bearer ticket or new signing-key service is introduced. Observed connection loss fences delivery immediately; a silent partition still has the bounded unexpired tail. Exact framing/domain separation and source/consumer session binding require review before wire implementation. Credits are not transferable, mountable paths, login capabilities, renewal or source grant replicas.

Origin issuance uses current local authority checks before and after the canonical chunk preparation; reserve chunk credit/byte/work budgets transactionally or under a source-generation CAS before publishing it. The final issuance fence binds the same epoch, so concurrent revoke cannot issue a new valid credit after the revoke transition. Every not-yet-handed origin data fragment also checks the original credit/source epoch and deadline before its guarded transport handoff; a locally observed origin revoke stops further handoffs immediately. Already handed immutable fragments count as disclosed even if socket/application delivery completes later. Count logical transport disclosure at that owned handoff, not when a consumer says it used data. Actual wire retransmission bytes are a separate network measurement. Control messages for revoke are independently bounded and can close the exact socket without waiting behind a stalled data write.

The receiver assembles only the exact credited canonical chunk in its already reserved slot and verifies the **whole** chunk hash against the authenticated immutable manifest before any application delivery. Partial fragments are never independently blessed as a complete manifest chunk. An application read of at most one MiB may span up to two chunks; acquire both exact credits and check both complete chunk hashes. Before **every data-bearing** FUSE read response, check fresh local authority/close state and every required origin credit's deadline/current epoch/binding/unspent allowance in the same final handoff decision. Atomically debit each credit by the response's exact intersection with that chunk; a repeated/overlapping read spends its full response bytes again. No partial debit followed by a retry may create permission. Request a fresh current-authority credit when allowance runs out; old possession or a new application request ID never refreshes it. Metadata, open, stat and list operations remain S-style fresh-origin operations, not data-credit permissions. Replayed request IDs and duplicate credit frames never reset spent allowance. Failed/duplicate/out-of-order/unknown frames do not manufacture new lifetime or memory slots. Prefetched bytes under expired or recalled delivery authority are discarded before serving another response; data possession alone never grants delivery authority.

The adapter can fetch a canonical one-MiB chunk while the application asks for ordinary 32-KiB pieces, and can keep bounded next chunks in flight. Slots are reserved before requests; pending credits, incomplete chunks and ending work count with ready/pinned chunks, rather than only counting the visible cache. It keeps FOPEN_DIRECT_IO and zero kernel read-ahead/cache, so all responses pass its local guard. The [kernel FUSE I/O documentation](https://kernel.org/doc/html/latest/filesystems/fuse/fuse-io.html) distinguishes direct I/O from cached read-ahead. The [SFTP v3 draft](https://datatracker.ietf.org/doc/html/draft-ietf-secsh-filexfer-02) permits outstanding requests, but that does not create future requests from a sequential application. The actual current codec payload cap is **262135 bytes** (256 KiB minus nine bytes of DATA overhead), with one normal response per READ and eight outstanding transport credits. Thus a full one-MiB manifest chunk needs **five READ/DATA response pieces** (four capped pieces plus the 36-byte remainder), not one fragmented response or an assumed four. Bind every piece's ordinary request ID/offset/length to the same exact F credit and charge transport slots separately; never exceed eight transport credits or leak a slot on partial failure. At the origin, duplicate/overlapping fragment requests consume their full disclosure allowance or refuse; lost replies do not roll back already handed bytes. F adds a separate negotiated bounded control contract and user-space cache; stock SFTP has no implicit F credit support.

The local delivery linearization point is the single guarded ownership handoff of an already verified immutable response to the owned FUSE/transport boundary, with current local epoch/time and all required chunk-credit checks plus remaining-byte debits performed once in the same decision. Prepare/verify data before that final check; an earlier check in a fetch goroutine is not the handoff. A failed/unknown later kernel write or acknowledgement never refunds already handed-off authority. A two-chunk response cannot borrow one valid credit to cover the other expired/revoked credit. Bytes already handed to library/kernel queues are already copied/disclosed even if application arrival is delayed. The 250 ms bound does not promise application-observed arrival deadlines or erasure of queued bytes. The actual go-fuse response path must establish this handoff/fence in tests; a check earlier in an unrelated asynchronous task is insufficient. No bookkeeping mutex may span an unbounded kernel/socket write. No adapter may enable F without proving this exact per-response boundary and uncached/owner-only behavior; the current Linux FUSE path is a candidate requiring new acceptance, and a future authenticated macOS adapter needs its own equivalent proof. This does not remove the full macOS mount requirement.

**Revocation tradeoff:** remote authorization at each local delivery is the unexpired delegated credit, not a fresh origin call. Source revoke stops issuance and sends a new epoch/abort; observed revoke immediately fences further local responses. During partition/notification delay a previously issued credit may authorize delivery for its remaining approved lifetime. This tail is part of F, not an implementation accident. No new/renewed credit is obtained offline. Policies requiring immediate origin consultation select S. Pretending a cached grant is current after that tail is forbidden. A malicious recipient host can retain prefetched data indefinitely, like any authorized recipient; the bound governs cooperating ARM delivery, not information erasure.

## Clock and expiry contract

Each authority uses its own runtime-only, validated suspend-aware elapsed clock and conservative wall/certificate checks. Linux [CLOCK_BOOTTIME](https://www.man7.org/linux/man-pages/man2/clock_gettime.2.html) includes suspend; Apple [mach_continuous_time](https://developer.apple.com/documentation/kernel/1646199-mach_continuous_time) also includes sleep. Reading the primitive, boot/time-namespace domain, conversion/overflow, capability/error and suspend behavior require actual platform tests. Go's ordinary monotonic values cannot simply be serialized across hosts or restarts ([Go time](https://pkg.go.dev/time#hdr-Monotonic_Clocks)). No newly serialized UTC timestamp or ordinary timer callback is treated as equivalent evidence.

For each credit request, after reserving its bounded ownership slot, the consumer records its local elapsed start and nonce **before** transport admission, queueing or sending. On a verified credit response it computes a deadline anchored to that original start, bounded by the approved 250 ms, the origin's granted remaining duration and its own remaining lease. The entire request/queue/transport/verification delay consumes that budget; receiving a delayed response or later fragment never starts a fresh lifetime. For a nonce, establish an immutable local cap at request start; a validated reply may only lower it. Replayed, conflicting or out-of-order frames never raise an established deadline, reset serial/spend state or replace the original anchor. Accept legitimate out-of-order replies only by matching the already reserved exact nonce/slot, without treating arrival order as fresh authority. Serial overflow refuses/ends the session rather than wrapping. Origin duration is itself bounded by its current remaining publication/storage/consumer/grant/certificate lifetime. Local checks after chunk verification and before response must still precede that deadline. Reject nonpositive remainder, overflow, backward/unknown clock, changed boot/time namespace or inconsistent wall-quality observations.

250 ms is a maximum validated elapsed-clock budget, not a hard universal real-time latency guarantee under arbitrary hardware/clock compromise. The approved scheme trusts each OS's validated elapsed clock rate; uncertainty or detected discontinuity denies delivery instead of adding grace. Scheduler stalls do not extend a credit because the synchronous delivery check reads time again; sleep cannot extend it on a supported clock. Restart drops every runtime credit and rejects replay into the new boot/session. Durable leases preserve ordinary expiry/unknown obligations; they never reconstruct a credit from a wall timestamp or last stored duration. Recovery requires fresh authority and a new bounded session, not a longer old lease.

Disk ceilings are cooperative reservation unless a verified enforcement mechanism says otherwise. No new root quota, sysctl, filesystem feature, kernel extension, service setup or dependency install. Unsupported clone/seal/user-mount facilities produce exact capability labels and bounded ordinary copy fallback only when the reviewed disk/memory plan allows it. A failed optimized mode never silently switches security or mount semantics.

## Failure, recovery and audit

Persist immutable intent before allocation/copy/credit exposure. Journal create/reserve/copy/seal/verify/publish/admit/credit-epoch/recall/ending/join/retire/reclaim with authenticated actor, UID+username attribution, reason, host/generation, exact policy hash, resource ledger and original operation key. Per-32KiB data reads are counters/structured bounded diagnostics, not an unbounded SQL event per packet. Credit issuance/replay state is bounded per session; durable session/epoch fences and conservative restart invalidation prevent replay without an unbounded per-byte journal.

Lost replies query the same key. Do not blindly repeat a copy, generate a second clone, republish or resume a stopped generation. Reconciliation checks exact managed identity, manifest, worker/native scope and journal state; unknown completion keeps disk/CPU/memory/FD/consumer obligations. Old process IDs are not new signal authority. Corrupt/unsupported optional rows refuse this feature and retain evidence, without disabling unrelated ordinary expiry. Whole-ledger proof/reset/uninstall must recognize the new rows and refuse unresolved duties; never erase an unknown snapshot to recover capacity.

Recall first fences admissions/credit epoch and ordinary lease authority; then stops exact owned fetches/streams, closes data/control and object handles, and joins callbacks/workers. Consumer settlement needs ordinary unmount, FUSE server join, adapter+prefetch drain, zero handles, exact remote close/settlement or retained unknown duty. Origin generation retirement follows all consumer settlement, copy join and native FD/cache drain; storage reclaim separately verifies identity/mount boundaries. Namespace disappearance/unlink, timeout, stop acknowledgement and empty known PID list are not reclamation. No forced/lazy unmount or arbitrary recursive delete fallback.

## Tests, formal obligations and prototypes

Before operator approval: review these texts and source-only closed record/codec/model designs. A separately reviewed isolated test-only synthetic prototype can compare (a) strict live path, (b) independently copied manifest/held-object verified reads with no real grants, and (c) a simulated chunk-credit adapter with virtual time.
