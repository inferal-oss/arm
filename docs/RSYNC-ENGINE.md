# Embedded rsync transfer engine

`internal/rsyncengine.Run` performs one standard protocol-27 exchange over an already authenticated caller-owned duplex stream. The four roles cover Go or system-rsync peers acting as client/server and sender/receiver. This is an internal staging component, not a public `arm sync` command, a daemon or an SSH authorization layer.

The main module includes a source-preserving fork of `gokrazy/rsync` v0.3.8, pinned to commit `7a9e59b40898516def209eb944c49f2ba42d4007`. Its BSD license and upstream source remain under `third_party/rsyncgo`; `ARM-CHANGES.md` identifies the reviewed changes and packaging namespace. The fork has no active nested module or local replacement, so versioned ARM installation includes its source. Original module metadata is retained as non-active provenance. Normal ARM builds remain CGo-free.

The fixed option subset transfers recursive directory contents, optionally preserving symlinks, permissions and modification times. It always evaluates deltas rather than trusting size/mtime quick checks. Arbitrary flags, ownership, ACLs/xattrs, hardlink topology, sparse layout, compression, special files, filters and rsync deletion are not enabled by this API. ARM's reconciler/publisher owns exclusions and exact removals, rather than handing deletion authority to a wire list.

Hard bounds cover signatures, blocks, literals, total entry count, paths, symlink targets and 64 GiB file lengths before allocation/use. The receiver confines operations through `os.Root`, but its input root must be a separately owned private staging directory. This does not replace native current-root binding, collision/metadata checks, reviewed overwrite/removal preconditions, quarantine recovery or publication. Source/metadata changes and rsync IO-error behavior can leave partial staging; a nil transfer error or peer statistics do not establish a complete expected tree.

Protocol 27 uses MD4 as its transfer checksum. Before publication ARM must verify the complete expected manifest and modern content hashes, then journal each native outcome and confirm the bidirectional baseline only through both endpoint receipts. `Stats` is progress information, including peer-supplied values, never resource settlement or completion authority. The caller separately owns resource admission, cancellation/expiry, transport join and retained staging obligations.

Review fixes reject negative filename lengths before allocation, remove an independent fresh-file hash reader that could outlive an early error, handle final bytes returned with EOF and fail stalled readers, and recheck changed source lengths on the delta path. Fresh-file hashing now uses the exact original read stream. Tests cover these ownership/bounds controls, corrupt/range tokens, containment, push/pull deltas, cancellation and real rsync peers in both roles. An actual ARM leased TLS/SSH backend fixture also verifies push/delta/pull, file hashes and exact destination lease/key receipts; it is not the public sync/source-orchestration workflow.

Run `make test-rsync` for the wrapper and nested fork suite. `make test` and `make check` explicitly include the nested module because Go's root `./...` does not traverse it. Installed system rsync is used by interoperability tests when present. A Linux oracle can be unpacked from verified distribution packages into an owned temporary directory; it is not an ARM runtime dependency or system installation. See [the validation record](VALIDATION.md) for actual scope and retained failures. No encrypted-link throughput target has been accepted yet.
