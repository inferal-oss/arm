# Unix source custody needed before native bind

Status: target custody contract. The isolated private binder candidate can bind and close one original Unix socket; it exposes no public forwarding route or accept worker. Restart recovery for bind intent or bound sockets is not implemented. Ordinary TCP forwarding admission and its CPU/memory promise are unchanged.

## Charged parent and immutable pair

Before any `mkdir`, socket bind, or pathname publication, acquire a separate ordinary managed-storage lease with a positive, finite Disk promise. Its purpose must be forwarding Unix source metadata, with a dedicated request key and reason. Do not treat the source listener's 4 MiB Memory promise as Disk or widen `AcquireForwardListener` to accept Disk. The storage lease must be current, active, on the same host and owner, and its deadline must cover the listener's remaining entitlement and cleanup window. Only the original Manager-issued listener and an original held storage directory may create the pair; a persisted row, PID, recovered TCP listener, client-supplied path, or `ForwardSourceBinding` field cannot do so.

Persist a versioned, immutable pair before bind: source lease ID, source request key and exact source binding; storage lease ID, original artifact identity and root identity; one generated socket basename; bounded Disk promise; and a `planned` phase. The pair must have its own forwarding purpose and cannot be reconstructed from a Kubernetes source permit. Exactly one live pair per source, one socket entry per pair, and no reuse after a terminal or uncertain attempt. Durable schema validation must reject incomplete, duplicated or contradictory pairs. An older reader must refuse the new schema rather than ignore a charged pair.

## Bind and observation order

Hold the original private managed directory FD and check its named identity, mode, owner, mount and storage parent against the pair. Survey the empty intended directory and record a durable pre-bind observation acknowledgement. A missing, failed or ambiguous acknowledgement denies bind. Bind one generated Unix pathname beneath that directory, retain the original listener FD and held directory FD, disable implicit unlink-on-close, and record the pathname entry's original filesystem identity. Check the held directory and named pathname again, then survey the entry and record a bounded post-bind observation/debt acknowledgement before admitting any local client. If bind, observation or persistence has an unknown result, retain both charges and deny exposure. The Disk promise is a reservation, not a filesystem quota; an observed allocation over the promise must remain charged and block activation pending an explicit accounting resolution.

The current generic `storage.Provider.Survey` is **not** a sufficient socket proof. It walks entries and sums `st.Blocks`, but does not specifically validate a Unix socket entry or prove that its live listener FD belongs to that pathname. On Darwin, its mount check opens each entry with `O_EVTONLY`; socket compatibility needs native evidence. Directory metadata may not appear in the entry's `st.Blocks`. Add and test a socket-specific held-directory entry check and a native allocated-block observation before using the survey as bind or cleanup evidence. Do not infer socket ownership or closed descriptors from a zero-byte survey.

## End, crash and recovery

End/expiry cancels the exact child first; it never settles either charge. Stop admission, join every accepted worker, close the original listener FD with checked error, unlink only the original named socket entry by the held directory FD after identity check, and positively close that held FD. A failed or uncertain close/unlink/identity check invokes `MarkCleanupUncertain` before the child join closes. Parent settlement waits for the child join and cleanup proof. The storage lease remains a consumer dependency until the pair is durably terminal; `End(storage)` and storage cleanup cannot bypass it.

After a daemon crash, no row adopts a new live child. Startup retains an unfinished pair and both charges. Recovery requires the exclusive daemon lifetime fence, exact storage artifact/root and socket pathname identities, proof that no original listener FD can remain, checked unlink or verified original absence, a complete provider survey, and durable acknowledgement before either charge settles. A TCP port probe alone is insufficient. If any pair state, storage identity, socket identity, pathname result, provider survey, or old-reader interpretation is uncertain, retain the debt for operator resolution. No application stream receipt is implied by cleanup.
