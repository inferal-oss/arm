The daemon snapshots its effective OS UID and optional OS account username at startup. UID remains local OS authority; remote API ownership additionally uses the authenticated source host principal. Username is display metadata from UID lookup, never an environment/caller name. Lookup waits at most 250ms with at most one outstanding native call process-wide; failure or invalid names fall back to UID. New leases/messages/pools and journal events retain that snapshot; incidents/resource consumers copy their lease owner. Pool changes record the current actor separately from the original creator. Existing UID-only history is not backfilled or relabelled after an account rename. Terminal output combines name and UID; JSON keeps independent fields.

The daemon stores a stable host ID and authenticated local owner identity. `localhost` resolves to that host ID. Leases reserve CPU, memory, and disk budgets together. Queued work holds no partial grant, and older queued work blocks renewal and queue bypass. Start time and expiry begin at grant rather than queue insertion. Acquisition idempotency keys reject mismatched reuse.

Interrupted local CLI acquisitions cancel by request key, including when the grant response was lost. Remote mutations instead preserve their authority/key and report uncertain outcomes; they never silently rerun or infer cancellation from a disconnected caller. A durable cancellation marker prevents a late request from becoming a new allocation after its cancellation arrived first.

CPU defaults to logical CPU count minus one. Memory defaults to current host availability (`--memory auto`); disk defaults to current nonprivileged availability on the state filesystem (`--disk auto`). ### Live memory admission

A separate nominal one-second collector publishes an exact-integer native host headroom estimate outside the admission lock. The pool is the smaller of that estimate and an optional operator ceiling. Outstanding promises are charged in full: available is `max(0, pool - reserved)`, with a separate shortfall if reservations exceed the pool. Grant and queue decisions use the cached estimate under the manager lock. Missing/invalid readings, negative clock age, or observations older than three seconds fail closed for new memory grants and memory renewals. Freshness checks native UTC time as well as elapsed time, covering suspend and clock changes. CPU/disk-only work remains subject to ordinary FIFO admission.

Existing claims survive shrinking capacity; renewal is refused during a memory shortfall. Exact acquisition retries return their original leases after capacity changes. Requests above an optional ceiling or fresh known physical RAM are rejected. Queued requests are revalidated if later known physical inventory proves them impossible; temporary memory headroom shortages remain waitable. Samples are ephemeral, without a durable event per reading. Status exposes source, freshness, ceiling, current pool, promises, available capacity and shortfall; the dashboard refreshes these without needing a lease event.

macOS estimates free plus pageable file-backed pages through public Mach counters. It does not add overlapping speculative/purgeable/inactive lists, anonymous inactive data, compression or swap. File-backed caches may require writeback. Linux uses exact `MemTotal`/`MemAvailable` from bounded `/proc/meminfo` reads; malformed/duplicate counters fail closed and telemetry shares the parser. Both are advisory host estimates, not hard quotas, memory-pressure scores or allocation guarantees; Linux cgroup allowances are not inferred.

ARM does not yet credit verified exclusive resident consumption against promises: sampled group footprints may contain shared/compressed allocations. Charging full promises on current headroom can over-reserve once jobs allocate memory. Attribution-aware unconsumed-reservation accounting, deduplicated resident credit, container/owner allowances, human/OS headroom, unified GPU-memory pools and richer pressure policy remain work. Replacing the executable does not change an older running backend’s startup policy.

### Live disk admission

An independent nominal one-second sampler reports exact native `statfs` user-available bytes for ARM's state filesystem. The effective pool is fresh availability bounded by an optional positive ceiling. macOS optionally applies the lower APFS shared-container free bound; failure to discover optional topology retains the valid native reading and records uncertainty. Linux preserves shared-backing uncertainty for relevant filesystems. Volumes are never added as independent capacity. These cooperative claims do not locate arbitrary workload writes or guarantee quotas on other mounts.

All outstanding disk promises stay charged, including uncertain/reclaiming provider states. No allocated-file, clone/snapshot or namespace-deletion credit is inferred. Exact arithmetic refuses negative/overflowing accounting. A falling pool preserves claims and exposes a shortfall; fresh headroom is required for relevant admission/renewal. Zero-disk work remains independent of disk pressure. Mutable free space/filesystem size never makes a request permanently impossible: only a configured positive ceiling does. Queued disk work receives explicit blockers and an unknown time estimate. Policy and peer-grant zero still mean zero allowance; only daemon configuration zero represents auto.

Cached availability expires after three seconds using wall and monotonic age. Collection waits at most one second with one native call in flight; an uncancellable stuck syscall can retain one worker until it returns, without multiplying workers or indefinitely blocking shutdown. Filesystem identity replacement invalidates the reading until restart/revalidation. Status and both dashboards distinguish live pool, full promises, to-lease amount, ceiling, shortfall and unknown/stale observations; human help hides collector details behind disclosure. Ordinary explicit start/serve arguments determine startup policy; changing the executable does not reconfigure an existing daemon. Automatic mesh setup replays the persisted configured launch policy, described below.

Each state directory is an independent authority. Separate test instances do not coordinate their budgets; cooperating agents must use the same ARM instance. Resource rows carry stable host, resource, and budget-pool IDs.

Peer messages are not local operator policy, and permission to prompt a powerful agent is a substantial trust grant. No peer can forward an operation through the receiver's identity to a third node.

TLS1.3 mutual authentication uses normal X.509 purpose/SAN/time checks plus exact self-signed non-CA Ed25519 DER and SPKI pins. Actual HTTP transport uses `http/1.1` ALPN, a dedicated `/v1/mesh` endpoint and explicit version/final-host envelopes. No system trust fallback, shared CA/password, session resumption or redirects are enabled. The closed remote API excludes native tokens/browser tickets, trust administration, shutdown, installation, message history and streaming subscriptions. Private files use owned-directory FD traversal, no-follow single-link files and bounded fsync/rename persistence. Accepted sockets, pre-body per-peer/global concurrency, request/response bytes and operation duration are bounded. Trust changes retain actor/time/reason/identity/grant digests; limits are 64 peers, 1,024 trust events and a 1 MiB configuration, with refusal rather than silent history deletion when full.

`mesh revoke` blocks new authorization and closes existing peer sessions; committed work remains local obligations. `mesh renew` explicitly recovers/renews even an expired local certificate with the existing private key/SPKI, changes the certificate pin, closes sessions and revokes local peer grants. Reviewed `join --replace-revoked` is required on both sides; active trust is never silently replaced. Private-key rotation is not implemented. A failed trust write is not reported as durable success; inspect uncertain/interrupted setup before changing keys or reissuing work.

Each host remains authoritative for admission, inventory, process identity, expiry and reclamation during disconnection. Initial remote claims refuse queues, custom-pool bundles, managed storage/port/agent attachments, usage-policy attachments and cross-authority atomicity. Direct-only SSH rejects ProxyJump/ProxyCommand and disables forwarding, first-contact/DNS trust, host-key mutation, multiplex reuse and unsafe configured commands/environment propagation. Remote browser/TUI selection, remote event subscriptions, automatic discovery/NAT/relay, placement, replicated global pools and distributed transactions remain work. Full policy is in [MESH-SECURITY.md](MESH-SECURITY.md).

## Execution and recovery

The backend launches commands in owned process groups and records their PID before opening a pipe gate that permits execution. Parent death before launch authorization closes the gate, preventing user work from starting without a durable process record. Command arguments are passed as an argument array; the fixed gate script executes them through quoted `"$@"` without evaluating their contents.

Expiry, cancellation, and release terminate a supervised group, first gracefully and then forcibly after a bounded interval. Parent exit also triggers cleanup of remaining group members. Capacity remains charged until the group is absent, or the lease becomes `needs_attention`. Processes that deliberately escape the group are outside this initial containment capability. There are no CPU or memory kernel limits yet.

A restart never signals a persisted PID. Recovered jobs with an extant or uncertain process group remain charged and require attention. `arm reconcile LEASE_ID` can confirm that the group has disappeared before returning its allocation. Jobs that never passed the launch gate, or whose recorded group is already absent, are recorded as interrupted. Graceful backend shutdown cancels its supervised work; the ordinary stop command refuses outstanding leases; explicit wait/force modes follow the provider-aware workflow below.

### Bulk actions and deliberate shutdown

`arm release --all` and `arm cancel --all` capture outstanding leases for the selected local authority and authenticated owner. An optional `--key` pins exact retries: scope and its event commit before any lease is ended, so retries after restart cannot include later work. Consumers precede managed storage/port parents. Every lease uses the ordinary provider path; the report shows partial failures and remaining allocations. ID and `--all` are exclusive; local bulk `--key` requires `--all`. Single-lease remote lifecycle operations separately accept `--key` for exact remote retries; remote bulk is not exposed. Response size remains bounded by the shared API limit rather than paginated bulk output.

`arm stop` remains idle-only. `arm stop --wait` pauses admission, renewal and pool changes, immediately cancels queued requests and lets active work finish or expire. `--timeout SECONDS` requires wait and positive integral seconds; after its backend-owned monotonic deadline it requests ordinary release. `arm stop --force` requests that release immediately. Inspection, cleanup/reconciliation and communication remain available during drain. Unverified storage, foreign ports and recovered group identities remain charged; force never bypasses ownership checks. Blocked shutdown leaves the backend available with admission paused until obligations are resolved.

A backend worker owns continuation independently of the requesting socket/CLI. Reconnecting preserves the original deadline; force can escalate it. SIGINT ends only the waiting client with exit 130 and an explicit continuation message. Intention and queued-cancellation scope persist before side effects; persistence failures cannot erase a previously committed timer or strand an already-started drain without its worker. Backend restart journals interruption and resumes ordinary admission after recovery; reboot-persistent shutdown is not claimed. CLI success requires endpoint removal, released authority lock and the matching durable ready record opened read-only, so an external crash/termination cannot masquerade as settled obligations.

Raw leases recover with their original deadlines. Terminal outcomes and resource ownership survive restart. Expiry is checked periodically by the live daemon; this initial version does not install an automatic restart service. Pre-execution launch failures now become terminal with a recorded failure detail, releasing execution claims and storage-consumer obligations. An external watchdog remains planned.

## Protocol

`internal/client.Session` supplies a persistent native connection for shared requests, durable events and monitor telemetry. It uses the existing endpoint/Bearer authentication and v1 protocol; older CLI call/follow interfaces remain available. Four concurrent requests have per-ID responses, exact `json.Number` decoding, a 15-second upper timeout and context-aware serialized frame writes. Durable events buffer 64 entries, then close with an explicit resynchronization error rather than silently lose history. Telemetry keeps one latest page and marks skipped incremental history as a gap, keeping replies independent of slow rendering.

Monitor controls alone serialize through a context-aware gate. Successful acknowledgements activate/clear subscription identity in reader order; rejected or unsent cancelled replacements retain the current stream. A sent control with an unknown outcome closes the connection for fresh inspection. Close ends transport only. Requests/mutations never retry automatically, and loss of a response cannot prove rejection. Session does not implement automatic reconnect, snapshot reload or the TUI; those remain consumers' responsibilities. The existing 4 MiB frame limit still applies to unpaginated snapshots.

The CLI uses `/v1/ws` on the daemon's selected loopback address. A protected `endpoint.json` file contains discovery information and an authentication token. Browser requests also undergo origin checking. There is one authority per state directory, enforced with an operating-system lock. The current permission model trusts clients operating as the same OS user with that token; separate operator and agent credentials remain to be implemented.

Protocol version 1 uses the envelopes in `internal/model`. Operations include `status`, `resources`, `usage`, `incidents`, `ports_discover`, `storage_inspect`, `storage_list`, `storage_preview`, `storage_cleanup`, `storage_handoff`, `acquire`, `run`, `inspect`, `release`, `cancel`, `cancel_request`, `renew`, `reconcile`, `output`, `events`, `subscribe`, `agents`, `register`, `message`, `messages`, and `shutdown`.

Events have durable increasing sequence numbers. `status` returns a snapshot cursor; subscribing after that cursor recovers changes after the snapshot. Requests and event streaming share a WebSocket connection and retain request IDs. Bounded output queues disconnect slow clients instead of growing indefinitely. Operation history currently has no pruning policy, and full lease snapshots are intended for the small local milestone rather than unlimited historical workloads.

`resources` exposes the current pool, reserved and available quantities, units, accounting method, and consuming leases with owner, agent and project attribution, purpose, state, and expiry. CPU/disk availability remains a reservation figure; memory also follows live estimated headroom as described above. The separate `measurement` object contains timestamped physical observations with unit, scope, method, quality, completeness, and diagnostic detail. The compatibility `observed` scalar, when present, is the measurement's host/filesystem `used` value, not a lease's usage.

### Host and storage observations

The cached resource observer samples every five seconds outside the admission lock, with a two-second deadline for native commands. CPU inventory reports process-visible logical CPUs; utilization comes from the separate monitor. macOS memory uses `hw.memsize` and public Mach free/file-backed counters; Linux uses `MemTotal`/`MemAvailable`. These share the availability interpretation used for memory admission, with explicit host scope and uncertainty. Permission failures remain unavailable values, not zeros.

Disk measurements use `statfs` for the filesystem containing ARM's state directory. They do not describe all host disks or establish where each disk reservation will be consumed. On APFS, native `diskutil` XML metadata identifies the volume and shared container UUID and reports container total/free separately. Container free is not a promise of allocation through a volume quota, nor does it include hypothetical purgeable capacity. Volume capacities must not be summed as independent pools. When the metadata API is denied, the container identity and pool capacity stay unknown. Linux reports filesystem type and mount-session identity; Btrfs, XFS, ZFS and overlay pool/extent accounting remain to be implemented.

`arm storage inspect PATH` uses the backend to walk a directory through rooted operations, without following symlinks or child mounts. It distinguishes logical file length from reported allocated blocks, deduplicates hard links within the walk, and leaves exclusive and reclaimable bytes unknown. Clones, snapshots, external hard links and open files prevent interpreting those counts as space that deletion would return. The non-atomic walk excludes directory metadata and states that scope explicitly. Entry count, nesting, command output, duration and simultaneous scans are bounded; incomplete walks return explicit partial measurements. Inspection is read-only and grants no adoption or deletion authority.

Stronger workload accounting, attribution-aware pressure policy, stronger filesystem providers, and confirmed physical reclamation remain planned. Read-only inspection is separate from the managed ownership protocol below.

### Managed storage leases

`storage create` requests a disk-only lease with its own TTL, purpose and identity. Provisioning records its intention before creating a new directory under the private state directory's managed root, then records the directory identity before returning it. Existing directories are not adopted. `storage list`, normal lease inspection and resource consumer rows expose these obligations. The managed root's identity is persisted in SQLite; replacement roots or missing identity records do not authorize guessed cleanup. Persistent directory checks include device, inode, UID and creation time so inode recycling alone cannot pass the comparison. Linux filesystems without creation-time or mount-ID support report this cleanup capability unavailable. Device identity changes on remount remain a conservative needs-attention condition.

Supervised `run --storage ID` attaches a durable consumer relationship and supplies `ARM_STORAGE_DIR` and `ARM_STORAGE_LEASE`. The storage deadline must outlast the execution TTL, including renewal. Ending a command releases its execution claims while leaving outputs and the storage reservation active. Multiple supervised consumers can share one lease; cleanup waits for all of them. Releasing or expiring storage revokes only its attached ARM-supervised commands. Lost supervision blocks cleanup until those consumers are reconciled.

For `rust-build`, a managed storage attachment is required. The admitted helper creates distinct owned target/build/control directories, verifies supported configuration and installed tools, and receives separate compilation authorization. `lease.cargo` reports the actual paths and phases; aliases, wrappers and unsupported overrides are refused. Jobs remain cooperative and complete Cargo compatibility remains future work. No broad `cargo clean` operation is used against project or shared caches.

`make test-workloads` additionally exercises installed Cargo/rustc, Gradle/JDK and uv/Python against the compiled CLI and a private backend. Dependency-free Rust and Java projects compile offline; a generated local wheel exercises uv resolution, installation and an isolated virtual environment. Scenarios verify configured Cargo jobs and Gradle workers, real compiler failures/exit codes, cancellation during a build script/task/Python descendant, Python TTL expiry, exporting a runnable executable/JAR/zipapp, and removal of managed intermediate trees while exported outputs still run. Cleanup waits for observed quiescence, including single-use Gradle JVM shutdown, and keeps physical-reclamation uncertainty charged until explicit fixture handoff. Dedicated uv profiles, automatic runtime dependency discovery and shared-cache adoption remain work; owned local Gradle service profiles are described below; Cargo scenarios also exercise the explicit managed export/retention workflow below. Tool absence fails by default; explicit skips are not successful acceptance. Actual Linux arm64 acceptance uses private toolchains and a reaping init inside the test PID namespace. `scripts/linux-test-init.py` reaps adopted compiler/JVM children and propagates child exit/signal status; it refuses ordinary execution outside Linux PID 1. SSH isolation uses it, while the Docker harness already uses `--init`. This fixes test-environment zombie accumulation without weakening process-group accounting or changing runtime policy.

`storage cleanup ID --dry-run` checks identity, tracked consumers, filesystem/mount boundaries and open-file activity without changing data. Cleanup quarantines the verified directory through an exclusive rename, then removes at most 128 entries per step using descriptor-relative operations, without following symlinks. Linux uses mount IDs and `/proc` descriptor/mapping observation; macOS uses filesystem identity and native `lsof` fields. Open files or working directories, foreign ownership, unavailable observation, unverified directories and interrupted ambiguous operations produce `needs_attention` and retain the budget. Activity observation covers the same OS user and is not security isolation against privileged or deliberately hostile processes. Directory scans and process inspection have deadlines and limits; cleanup progress and failures are audited.

Namespace removal is recorded separately from physical reclamation. This provider does not prove exclusive blocks on snapshot/reflink filesystems. A populated candidate therefore remains charged after removal under `needs_attention`, with `namespace_removed` and the reason visible. Empty-directory cleanup can finish automatically. `storage cleanup` retries transient failures; it does not assert that unknown physical blocks were freed. `storage handoff` explicitly transfers remaining files and/or unresolved physical-allocation responsibility to the operator, records a terminal outcome and removes ARM's future cleanup authority. It refuses tracked active consumers and in-progress cleanup. Subsequent cleanup calls preserve handed-off data. Handoff is not a physical-free-space observation.

Storage leases, including unresolved cleanup, block ordinary daemon stop and uninstall. The existing uninstall guard applies to durable storage obligations even while the daemon is down. Files explicitly handed off remain user-retained under the recorded path; state and history remain preserved. Configurable managed roots, explicit adoption, shared-cache policy, remount identity resolution and filesystem-specific reclamation verification are still planned.

### Owned Gradle services and consumers

The local `gradle-service` profile starts an installed Gradle/JDK foreground daemon under ordinary captured-group supervision with an exclusive managed service home. `run --detach` is accepted only for this profile and returns the starting lease; inspect until `workload.state` is `ready`. A private generated no-op probe joins the verified owned group and binds readiness to native process identity, JVM start time, JDK, Gradle version/home, worker count and JVM flags. The service remains charged while idle. At least 512MiB is required: 256MiB is allowed for the startup probe before sizing the daemon heap/metaspace from the remainder. JVM settings do not bound total memory or CPU consumption.

`gradle-build --service ID` requires a ready matching local service, a separate client CPU/memory claim, explicit project root and separate managed output storage. Only one consumer runs per service; all parent deadlines must cover it. The adapter pins the installed executable/JDK/home/JVM settings, applies workers from the service's whole-core budget, disables parallel project execution/configuration cache/watch mode, and redirects standard project outputs beneath that consumer's managed directory. Detailed policy and commands live in `arm agents card gradle-build`; the general guide and installed instructions teach card discovery.

Before configuring the project, the init gate verifies the exact service JVM. Gradle's public client can still spawn a fallback daemon; an unexpected JVM refuses project work, blocks service reuse and preserves obligations. ARM never adopts or signals a PID obtained from receipts/logs. Consumer settlement requires both matching private start/completion receipts and absence of its own client group. Missing/replaced evidence stays charged; later valid completion can settle the original outcome and unblock a still-owned service. Ending a service handles its consumers before its owned scope. Restart loses signal authority and retains uncertainty; reconciliation observes absence/idle evidence without recovering control over saved PIDs.

Control files are bounded private same-user single-link regular files opened through anchored no-follow directory access, with directory birth identity, stable exact-schema reads and nonce-bound receipts. Workload evidence, lease projection and events are committed atomically. Public evidence excludes private receipt secrets. Export explicit JAR/runtime files through ordinary storage export, verify them, and then release intermediates. Logical namespace removal still does not establish exclusive physical reclamation.

`make test-gradle-services` runs real installed Gradle/JDK offline against a disposable backend. Native and actual Linux acceptance covers Gradle 9.8.1 (JDK27/macOS and JDK25/Linux). Wrappers, daemon JVM criteria, `buildSrc`, composite/included builds, continuous mode, remote services, queued/custom-pool/port attachments, arbitrary extra options, adoption and service reconnection after backend restart are unsupported. Arbitrary plugins/custom outputs/escaped children are not contained by this cooperative adapter; missing evidence remains unresolved. The initial service model serializes clients rather than allowing concurrent builds in one daemon.

### Preserving outputs and short retention

`arm storage export LEASE_ID DEST_DIR --file SOURCE[=OUTPUT] --reason TEXT` copies explicit regular files into a new independent bundle outside ARM state/managed roots. Repeat `--file` for required runtime data or libraries; discovery is explicit. `--dry-run` previews identities/paths without writes, `--wait` observes completion, `--key` pins an exact retry and `--revision` optionally binds source review. Existing destinations are never overwritten. Export does not release its source lease; verify the result, preview cleanup and use ordinary release when intermediates are no longer useful.

The provider requires verified idle owned storage and no queued/active consumers, rejects symlink/mount/foreign/external-hardlink sources, and supports Cargo hardlinks wholly inside the owned tree. Destination parent must be owned and protected from group/other writes. Independent output inodes retain safe executable/read modes. Directory FDs, birth/mount identities, source versions, full-tree link accounting, digests and exclusive publication guard changes; root protection, canonical parent and final contents are rechecked after hashing. These are conservative observations within the same-user trust boundary, not adversarial isolation or a kernel I/O deadline.

Durable planned/copying/ready/publishing/published phases precede external effects. Restart never blindly replays uncertain copying/publication. `arm storage exports [--lease ID]` lists compact latest-100 summaries; `inspect EXPORT_ID` shows full evidence, `reconcile EXPORT_ID` verifies a complete already-published bundle, and `handoff EXPORT_ID --reason TEXT` explicitly assumes remaining output responsibility without deleting it. Partial output is preserved, not resumed or automatically discarded. Unresolved exports block source cleanup/consumers/handoff; expiry ends entitlement while unresolved reclamation remains charged. Runtime activity is attributed to exact operation IDs rather than inherited by old exports from the same lease.

Work is bounded to two copy workers, 32 unresolved records, 64 files/16 GiB within the source promise, 100000 scanned entries, 30-second preparation and two-minute copy/reconcile. Copy deadline cannot outlast source expiry; stalled native filesystem calls remain subject to OS behavior. Destination space is an advisory availability check, not an atomic reservation or continuous output budget. Final outputs are operator-owned; APFS/shared extents still prevent claims of exclusive reclaimed bytes.

`arm storage retain LEASE_ID --ttl DURATION --reason TEXT` records a shorter justified intermediate lifetime, at most 24h, with revision checks and attached-consumer deadlines. It cannot extend entitlement; ordinary renewal handles extensions and clears the current retention projection while preserving its journal. Full Cargo configuration/alias/wrapper resolution, automatic abandoned-directory detection, runtime dependency inference, shared caches and web/TUI export editors remain work.

## Port leases and discovery

The internal port provider validates explicit TCP/UDP IPv4/IPv6 claims in the daemon's current network namespace. It selects ephemeral ports or bounded ranges, checks wildcard and dual-stack conflicts against a supplied reservation ledger, and attempts real kernel binds for the entire bundle. Failure closes sockets acquired earlier in the bundle. IPv6 sockets explicitly select IPv6-only or dual-stack behavior; TCP and UDP remain separate resources. Linux namespace identities include the boot ID; this provider does not enter other namespaces.

Held sockets can be passed to a child as inherited descriptors without closing and rebinding. The daemon's copy keeps the bind until explicitly closed, even after a child exits. Cooperative mode instead closes the probe socket and reports that it supplies only ledger coordination: a later workload bind can fail. Probes test the exact selected port and reject stale namespace identities. A successful probe is only a current observation, and socket inode metadata grants no process-control authority.

`acquire --port` combines port requests with resource budgets; `ports reserve` creates a dedicated port-only lease. Provisioning intent is durable before binding; actual selected bindings are recorded before success or execution authorization. Queued bundles hold no partial grant, and repeated identical bind failures do not generate new audit events every scheduler tick. A failed bundle releases its earlier descriptors and resource reservation. Idempotency compares normalized claim lists and command identity.

`run --port` defaults to inherited activation. The pipe gate occupies descriptor 3; `ARM_PORTS` gives each actual socket's descriptor (starting at 4), and `ARM_PORT_LEASE` identifies ownership. The process wraps these sockets rather than rebinding. `run --port-lease ID` attaches one command to a dedicated port lease; it cannot combine attachment with fresh claims, and the parent must outlast the child including renewal. The parent retains sockets for subsequent sequential consumers. Revoking a parent cancels its attached owned command and waits for reconciliation before closing its copies. Resource rows identify both the reservation and the attached consumer/reason; the latter adds no duplicate reservation quantity.

Release probes each exact binding after closing owned descriptors. An unrelated listener, escaped inherited socket or uncertain process group keeps the allocation charged. No inventory PID grants signalling authority. A restart marks consuming port allocations `needs_attention` with unknown descriptors; `reconcile` requires tracked consumers and saved process groups to be absent and current-namespace binds to succeed. Cross-namespace reconciliation is unsupported rather than silently probing a different namespace. TCP TIME_WAIT can conservatively delay successful reconciliation.

`ports list` returns allocated resource rows, including the protected backend listener; its resource ID is not a releasable lease. `ports discover` observes Linux `/proc/net` tables and descriptor/start-time identities, or macOS native `lsof` fields and process-start observations. Collection has time, output, entry and process limits, and exposes permission restrictions and non-atomic scope. IPv6-only/socket-sharing options are unknown in observations. Linux can match a held socket inode to its lease; potential ledger overlaps are reported separately from verified inode claims. Empty owner lists never establish free ports. GPU providers, richer socket-option observations and host-wide network budgets remain work.

On an ordinary Linux login, a same-user service may deny `/proc` activity access even though ARM owns its storage directory. The current storage provider refuses deletion and retains the budget in that case; it does not omit the service to obtain a successful scan. This occurs for `sd-pam` on the tested OrbStack machine. Explicit handoff remains available. The test harness verifies this degraded behavior directly and uses a private process namespace only for separate successful-cleanup fixtures; that isolation does not prove host-wide observation permissions.

## Installation and messages

Installation modifies only managed blocks in the selected Codex `AGENTS.md` and Claude `CLAUDE.md` files. It records the original content fingerprint, the exact installed block, creation status, and the device/inode identity of the containing root. Writes are atomic and preserve existing file permissions. A persisted intention can be resumed if interrupted before writing the block.

Uninstall refuses outstanding allocations, protects the backend authority boundary, and removes only unchanged managed blocks. It preserves unrelated later edits and reports edited managed blocks as incomplete. It rejects symlink instruction targets and replaced root directories. State and the recovery manifest remain; executable removal, purging, native service registration, and interactive drain/cancel workflows are not implemented.

Integration mutations are serialized with a separate lock. Daemon stop waits for the authority lock to be released, including database closure, before reporting completion. Existing shared or symlink state roots are rejected without changing their permissions.

Messages are persisted before delivery, with per-recipient results. Replies from the Claude adapter are also recorded as operator-inbox messages linked to their originating message. Messages interrupted in pending delivery become `unknown` on recovery; ARM does not silently resend potentially delivered messages. Reviewed sends have durable exact-request idempotency keys. Inspect an uncertain result by key; explicit retries retain the original audience and settings and never repeat native delivery for an already recorded message. Automatic native redelivery remains unsupported.

Codex uses the installed CLI's `queue --thread UUID --message TEXT`, with an optional local Unix endpoint. A queued result means the CLI accepted the message, not that the model read it. The live test separately observes a response from that same session. See the [official Codex command reference](https://developers.openai.com/codex/cli/reference/).

A successful delivery must report the same session ID and a successful model response; tools are disabled for this delivery turn. It cannot inject into an already running Claude session. See the [Claude CLI reference](https://code.claude.com/docs/en/cli-reference).

The Codex test fixture uses a separate native app-server and the installed version's protocol. ## Durable recipient inboxes

`agent register --delivery poll` selects an inbox without launching an agent CLI; active Claude sessions need no idle declaration. A generic polling adapter supports other agents. Existing contacts get persistent registration identities at startup; historical messages without verifiable recipient identities are not guessed or replayed. A new session/configuration identity gets a new registration, and retargeting a contact with outstanding attributed work is refused. Changes during a pending native delivery are also refused, and message creation rejects a stale contact/delivery snapshot.

Message creation and recipient fanout commit together. Each current broadcast recipient gets a registration-scoped inbox entry; contacts registered later do not inherit it. Native messages also enter the inbox as a fallback, while queued/responded/failed/unknown native delivery remains separate from polling receipts. Receipt data is stored independently so a late native result cannot overwrite it. These views narrow recipient selection within ARM's same-user trust boundary; session IDs and cursors are not independent authentication credentials.

`agent inbox` returns up to 64 items plus a host/registration-scoped opaque cursor and `more`. `--pending` filters explicit acknowledgements. Waits are bounded to 20 seconds, with 64 active inbox requests globally. The shared WebSocket reader multiplexes bounded concurrent requests (eight per connection) so long polling does not block ordinary responses or disconnect cancellation. `agent watch` prints JSON lines when redirected or with --json and readable events in a terminal, advances after successful output, reconnects with bounded backoff, and rejects registration changes. `--once` reads one bounded batch. This uses the existing request/response transport and durable inbox; it does not introduce a second authority.

Reading or streaming never implies receipt, acknowledgement or compliance. `agent receive` records receipt explicitly; `agent ack` records an acknowledgement and optionally adds a linked response to the operator inbox in one transaction. An identical retry preserves the original timestamps/reply ID, while changed response text conflicts. Retention policy, automatic incident routing and delivery retry policy remain work.

Installed instructions embed a native Markdown source at build time: commands, flags and JSON fields use inline code, and long send/reply examples use fenced shell blocks. No runtime Markdown dependency is required. Installed instructions describe background watchers/subagents where supported and polling before expensive work otherwise. ARM cannot ensure that a background tool's output reaches the main agent while it is busy. The real Claude check verifies a resumed exact session running `watch --once` and `ack` through Bash; it does not establish active-session injection or automatic subagent forwarding. Reinstallation upgrades only an exact unchanged managed block. A persisted pending-block record covers either side of its atomic replacement; preview is read-only, surrounding user edits and modes survive, and ambiguous/edited managed blocks are preserved for manual resolution.

## Counted coordination resources

`pool create` registers a cooperative counted resource with explicit host/global scope, stable ID, unit, capacity and creator identity. Global resources have no host locator; their current authority is the local daemon. `acquire/run --pool ID=COUNT` uses the ordinary lease lifecycle and combines pools/native claims without partial queued grants. Claims are sorted and duplicate quantities normalized with overflow checks. Dedicated storage/port commands remain specific to their resource kind. Custom-only acquisition defaults to zero CPU; supervised runs retain their normal CPU default and receive `ARM_POOLS` metadata.

Pool state, an append-only change entry, a durable operation-key result and an event commit in one SQLite transaction under the same admission mutex. Create, absolute set, signed adjust, rename/describe, drain/resume and delete record before/after definitions, capacities/delta, revisions, authenticated owner, optional agent ID/session/registration/project, reason and timestamp. Absolute/state/metadata edits require an explicit revision; atomic deltas may optionally supply one. Repeating an operation key returns its original result; conflicting parameters fail. CLI mutation errors retain generated keys for uncertain-result retries. History pages contain at most 100 entries and approximately 1 MiB of stored record data, with a sequence cursor.

Capacity may shrink below outstanding reservations, exposing a deficit rather than changing existing quantities or deadlines. New grants wait for room; deficit or draining pools deny renewals. Drain rejects new acquisitions while already queued work proceeds under normal capacity/FIFO rules. Delete requires no queued or consuming claims, keeps a tombstone/history and permits reuse of the display name with a new ID. Metadata edits preserve identity and scope/unit cannot be mutated. Resource views include exact counts, users/reasons, queued claims and deficit. Numeric wire fields remain JSON numbers; the Go client preserves them through generic decoding rather than converting integers to float64. Integer native budgets also compare remaining capacity before addition to prevent overflow bypasses.

These permits return after ordinary lease settlement. Recovered uncertain supervised work and unresolved bundled resources remain charged, including their pool quantities. Custom capacity does not claim OS enforcement or physical reclamation, and no external-service fencing adapter is implemented. Scope is represented for future multi-host pool coordination. The initial direct-peer mesh rejects all remote pool bundles; global replication/failover and distributed pool partition handling are not implemented. Built-in leases use the existing transactional event journal; built-in host-budget configuration does not yet have this capacity-change journal. Web and terminal custom-pool browsing, reviewed controls and paged journals are implemented as described below.

## Supervised workload observations

Launch captures PID, process group, UID, native start identity and boot/PID namespace before opening the execution gate. Failure leaves supervision available but usage attribution explicitly unavailable. Only the live owned job object enables sampling; persisted PIDs never restore monitoring or signalling authority after restart.

The sampler runs outside the admission lock on a one-second cadence, rotating batches of at most 32 jobs and 256 members per job. A shared two-second context bounds cooperative collection work; native kernel calls themselves are not preemptible. Snapshots validate the root before and after collection and each member around its counter reads. Metadata restrictions, races, bounds and missing counters expose incomplete or unavailable evidence. Samples older than three seconds are stale using elapsed time within the running daemon. No process environments or command lines are read.

macOS calls public libproc APIs through `github.com/ebitengine/purego`, retaining CGo-free builds. Runtime ABI checks and Mach timebase conversion protect counter interpretation. Memory is the sum of process physical footprints, including task-ledger compression/platform charges; it is not exclusive physical allocation. Linux uses bounded `/proc` reads, native `AT_CLKTCK`, boot/PID-namespace/start-tick identities and `smaps_rollup` Private_Clean plus Private_Dirty. This private-resident metric excludes shared mappings, swap and other unreported charges. Raw per-process RSS is separate and is not summed as group physical usage.

CPU compares cumulative counters only for identities present in two verified samples and uses the enclosing read interval. The result is a lower-bound core average, not instantaneous CPU or a complete accounting of short-lived/exited/escaped descendants. The first sample and unavailable counters remain null. `arm usage LEASE_ID`, `inspect` and `status` return scope, quality, completeness, timestamps and identity evidence. Samples remain in memory rather than generating one durable event per second; normal lifecycle persistence retains a final summary without member details. A fallback to an earlier verified sample is marked stale. Recovery never presents persisted usage as a live measurement. Per-workload telemetry history/streaming and kernel resource limits remain work; the separate host monitor below supplies host-level history and streaming.

## Observed overage policy and warnings

`run --usage-policy warn|revoke` opts into a resolved immutable per-lease policy and requires a registered agent plus a CPU or memory budget. The unpublished CLI and backend use the current `run` request together; compatibility with previous development snapshots is not provided. Window is bounded to 1s..1h, grace to 1s..24h and warning count to 1..10. Without this policy, observations cause no automatic action. A policy-enabled command cannot pass the launch gate without captured process identity.

Each resource gets a durable incident recording owner, exact session/registration, resolved policy, scoped evidence, revisions, warning message IDs and deadlines. Continuous observed breach must satisfy the configured window before the first warning. Further warnings are spaced by grace periods, and `revoke` requires the final grace plus a continuing sustained breach before recording its decision and calling the existing owned-job termination path. `warn` stops issuing messages at its configured count. CPU intervals longer than three seconds are unsuitable for this detector. Stale, changed-identity, unknown and gapped observations reset continuity and suspend escalation; a fresh partial lower bound can prove overage but cannot close an incident merely because it is small. A complete scoped observation within threshold closes it as `observed_within_threshold`, not proof of complete physical compliance. Incident changes, lifecycle events, warning message and recipient inbox entry commit together. Superseded warnings are retained historically without invocation. Every warning has polling fallback, independent receipts and delivery status. Native replies reach the operator inbox transactionally and idempotently. Delivery failure or acknowledgement cannot postpone policy or lease deadlines, and renewal does not reset an incident. Incoming replies are never executed or accepted as evidence of reduced usage.

## Host monitor backend
