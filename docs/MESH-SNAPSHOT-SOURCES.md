# Primary sources consulted October 25, 2026

These references describe platform/protocol primitives, not ARM acceptance results. All performance and lifecycle requirements in the proposal are design choices or separately pinned local evidence.

| Source | Narrow conclusion used | Consequence for ARM |
| --- | --- | --- |
| [Apple XNU clonefile manual](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/man/man2/clonefile.2) | Clone data is copy-on-write; support and metadata/ACL behavior vary. Directory cloning is discouraged. | Prefer explicit file copy initially. A tested descriptor-based clone can accelerate creation without granting immutable/sealed status. |
| [Linux FICLONE manual](https://www.man7.org/linux/man-pages/man2/FICLONE.2const.html) | Supported same-filesystem reflinks share extents with private later writes; per-file clone is atomic against concurrent writes. | No hardlinks or snapshot-wide atomicity inference; still verify and budget full-copy requirements. |
| [Linux memfd_create](https://www.man7.org/linux/man-pages/man2/memfd_create.2.html), [file seals](https://man7.org/linux/man-pages/man2/F_ADD_SEALS.2const.html) | Seals are inode-scoped and additive. WRITE, GROW, SHRINK and SEAL serve different purposes; FUTURE_WRITE leaves old shared writable mappings effective. | Read back required seals and charge volatile memory/FDs. This is optional Linux behavior, not durable portable storage. |
| [Kernel fs-verity](https://docs.kernel.org/filesystems/fsverity.html) | Supported filesystems can enforce read-only content integrity; metadata/names are still mutable, and digest authentication remains a separate responsibility. | No policy/sysctl/filesystem setup. Optional measured capability does not replace publication identity/grants/accounting. |
| [Kernel FUSE I/O modes](https://kernel.org/doc/html/latest/filesystems/fuse/fuse-io.html) | Direct I/O bypasses the page cache and kernel read-ahead. | Bounded user-space range fetches are a separate design; enabling kernel caching is not a silent performance switch. |
| [SFTP v3 draft](https://datatracker.ietf.org/doc/html/draft-ietf-secsh-filexfer-02) | The protocol allows multiple outstanding requests, subject to implementation/flow-control bounds. This is an Internet-Draft, not a final SFTP RFC. | Keep ARM's stricter packet/credit ceilings. A sequential application still needs an explicit safe user-space range-fetch mechanism for latency amortization. |
| [Go time monotonic documentation](https://pkg.go.dev/time#hdr-Monotonic_Clocks) | Runtime monotonic readings are process-local and omitted from serialized forms; clock behavior must be considered across sleep. | Never serialize a monotonic deadline as portable lease authority. |
| [Linux clock_gettime](https://www.man7.org/linux/man-pages/man2/clock_gettime.2.html), [Apple mach_continuous_time](https://developer.apple.com/documentation/kernel/1646199-mach_continuous_time) | BOOTTIME and Apple's continuous clock include suspended time. | Capability-test the actual elapsed source/domain; a timer or unsupported clock must not extend credits through sleep. |

No new platform feature was probed or enabled, no dependency was installed, and no protocol/private service was launched during research. Filesystem-specific availability, unprivileged sealing, suspend semantics and actual CGo-free bindings remain acceptance work. Arbitrary same-user/root interference is outside the supported strong isolation claim; the proposal does not infer that a clone or chmod removes that boundary.
