# Apple Screen Sharing protocol layer

These sources are adapted from [noVNC-ARD](https://github.com/peetinc/noVNC-ARD) at commit `d699293635083c9e0c30c8f9480993865653772a` under MPL 2.0 (`LICENSE.txt`). Imports point at ARM's vendored noVNC tree. ARM selects its already-tested Apple DH authentication type 30 when offered and uses only Standard quality. The High Performance support code is present because the protocol layer imports it, but ARM does not enable it or ship its media decoder assets.

No macOS credentials or framebuffer data are persisted by ARM. Standard rendering and Mac authentication have been observed through the mesh and a temporary Linux-origin direct socket. The browser sends Apple encrypted pointer records, and one fixed-point probe produced the requested pointer coordinate in the Mac daemon log. Clicks remained inert in the same-Mac browser and native bridge tests, including a temporary probe that suppressed ordinary browser mousemove sends. A later UTM guest browser controlled the guest itself; a delayed guest-to-host click at `(20,10)` opened the physical host Apple menu when the operator left local input idle. Host logs showed ignored moves during the nested live test, supporting local-input arbitration; sustained independent-physical-client control remains unverified. Temporary pointer diagnostics are removed. Text clipboard operations are explicit in the UI and covered by unit tests, but live transfer is unverified. The protocol implementation needs acceptance on a second physical Mac before it can be considered generally supported.
